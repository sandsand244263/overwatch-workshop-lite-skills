# 设置项：唯一值与那个老 BUG

设置项的值**不是随便写的**，游戏数据里每个键都有固定类型和合法值。表在 `data/settings.tsv`（键 / 类型 / 可选值，从游戏数据直接导出）。

## 一、三类键，三套写法

| 类型 | 怎么写 | 例 |
|---|---|---|
| **BOOL** | 只能写 `开启` / `关闭` | `允许切换英雄: 关闭` |
| **ENUM** | 照抄枚举原文（表里的 allowed） | `重装职责被动生命值加成: 禁用`、`英雄限制: 关闭` |
| **FLOAT / INT** | 数字或百分比 | `复生时间: 1%` |

## 二、那个老 BUG 的真相

工坊把设置项导出成文本时，**布尔项写的是数据里的显示词（`启用` / `禁用`），但导入器只认 `开启` / `关闭`**。所以复制出来的脚本原样贴回去会报错，手改成 `关闭` 就能导入（实测）。

数据能证明这不是我们理解错：547 条设置项里**没有任何一条布尔项把“假”写成 `关闭`**，全是 `禁用`；但 `关闭` 能进、`禁用` 不能进——说明导入器用的是另一套规范词。

## 三、为什么 `重装职责被动生命值加成: 禁用` 又能过

因为它**不是布尔项，是枚举**，`禁用` 是它的三个合法选项之一（`始终启用` / `1重装，2输出，2支援` / `禁用`）。

所以规则不能简化为“见到禁用就改成关闭”——只有 BOOL 项才那样，ENUM 项照抄原文。

## 四、报错长什么样

布尔项写错时，游戏报的不是“值非法”，而是指向块开头：

```
错误：第 N 行的"综合 {"之后应有一个游戏模式设置
```

定位方法：看那个块里第一个键值对，往往就是它。

## 五、表怎么来的（可复现）

游戏数据里有完整的设置项定义（`STUGameRulesetSchema`：每条带类型、布尔真/假词、枚举选项）。OWLib 自带的 `list-game-ruleset-schemas` 崩了，所以我们在 `workshop-data-update` 技能里加了自己的导出命令 `list-settings-words`，输出再压成 `data/settings.tsv`。数据更新后重跑即可。
