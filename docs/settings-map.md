# 设置项：唯一值与那个老 BUG

设置项的值**不是随便写的**，游戏数据里每个键都有固定类型和合法值。表在 `data/settings.tsv`（键 / 类型 / 可选值，从游戏数据直接导出）。

## 一、三类键，三套写法

| 类型 | 怎么写 | 例 |
|---|---|---|
| **BOOL** | 只能写 `开启` / `关闭` | `允许切换英雄: 关闭` |
| **ENUM** | 照抄枚举原文（表里的 allowed） | `重装职责被动生命值加成: 禁用`、`英雄限制: 关闭` |
| **FLOAT / INT** | 数字或百分比 | `复生时间: 1%` |

## 二、那个老 BUG 的真相

工坊把设置项导出成文本时，**布尔项写的是数据里的显示词（`启用` / `禁用`），但导入器只认 `开启` / `关闭`**。所以复制出来的脚本原样贴回去会报错，手改成 `关闭` 就能导入（实测）。

数据能证明这不是我们理解错：547 条设置项里**没有任何一条布尔项把“假”写成 `关闭`**，全是 `禁用`；但 `关闭` 能进、`禁用` 不能进——说明导入器用的是另一套规范词。

## 三、为什么 `重装职责被动生命值加成: 禁用` 又能过

因为它**不是布尔项，是枚举**，`禁用` 是它的三个合法选项之一（`始终启用` / `1重装，2输出，2支援` / `禁用`）。

所以规则不能简化为“见到禁用就改成关闭”——只有 BOOL 项才那样，ENUM 项照抄原文。

## 四、报错长什么样

布尔项写错时，游戏报的不是“值非法”，而是指向块开头：

```
错误：第 N 行的"综合 {"之后应有一个游戏模式设置
```

定位方法：看那个块里第一个键值对，往往就是它。

## 五、表怎么来的（可复现）

游戏数据里有完整的设置项定义（`STUGameRulesetSchema`：每条带类型、布尔真/假词、枚举选项）。OWLib 自带的 `list-game-ruleset-schemas` 崩了，所以我们在 `workshop-data-update` 技能里加了自己的导出命令 `list-settings-words`，输出再压成 `data/settings.tsv`。数据更新后重跑即可。

## 设置界面的六个分区（2026-10-20 现场核对）

| 分区 | 能否写进 .ow | 说明 |
|---|---|---|
| 预设 | 不能 | 官方/玩家保存的存档配置，复制脚本拿不到 |
| 大厅 | 能（部分键） | 我们已知 7 个键：地图轮换 / 返回大厅 / 比赛结束后转换队伍 / 玩家上限 队伍1 / 玩家上限 队伍2 / 观战者人数上限 / 队列中的玩家可以加入；界面上还有 队伍平衡 / 自由混战人数上限 / 比赛语音聊天 / 玩家断线时暂停游戏 / 数据中心设置 / 最低延迟 / 随时安装最新的抢先体验更新，这些写法尚未取得真实样本 |
| 模式 | 能 | 见 data/settings-blocks/ 的四份模式模板 |
| 地图 | 能 | 地图名 + GUID，全部在 data/maps.tsv（291 条） |
| 地图工坊 | 视内容 | 示例模式本身是独立模式，不是开关 |
| 英雄 | 能 | 英雄 > 综合 与 英雄 > 英雄名 同级；技能/武器键在 data/settings.tsv（技能 114 / 武器 33） |

写设置块时优先用 data/settings-blocks/ 的整块模板，地图列表从 data/maps.tsv 取 GUID。

### 大厅分区：已知 8 个键（实测样本）

```
大厅
{
	数据中心设置: 最佳设置
	最低延迟（毫秒）: 100000000
	比赛语音聊天: 启用
	玩家上限 队伍1: 4
	玩家上限 队伍2: 4
	玩家断线时暂停游戏: 是
	自由混战人数上限: 10
	队伍平衡: 攻防轮换后
}
```

- `最低延迟（毫秒）` 用的是**全角括号**，不能写成半角
- `自由混战人数上限` 只在**死斗类模式开启时**才出现（团队模式下不写）
- `队伍平衡` 可写 `关闭` / `攻防轮换后` 等
- 死斗这类无可调项的模式，在 `模式` 里是**单行无花括号**条目（`死斗` 独占一行），与赏金猎手同形

### 数据中心设置的选项

默认 `最佳设置`（一般不用改）。已知可选：`最佳设置` / `中国北京` / `中国成都` / `中国杭州` / `中国深圳`（界面可继续滚动，完整清单未取全）。

它不在工坊数据里（`workshop_zhCN.json` 搜不到“数据中心”），只能靠界面确认。
