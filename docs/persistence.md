# 跨重连持久化：键用名字，不用栏位

> 「玩家退出再回来，数据要还给他」这类功能（存档码、余额、任务进度、战绩）全部适用。
> 一句话结论：**`栏位(玩家)` 不是身份标识，拿它当缓存键，重连后 100% 静默失效。**

报错查 [errors.md](./errors.md)；判断能不能这么写查 `ws.py rule 栏位`。

## 为什么栏位靠不住

`栏位(玩家)` 是玩家**在房间里的排列序号**，不是账号。玩家离开后重新加入，会被分到别的栏位——
12 人房尤其明显（issue #11 用户实机：「加入的栏位是随机的」）。切观战也算离开比赛。

实测读数（L3，单人在 12 人房，一段存档码模式的查看器日志）：

```text
[00:00:13] 缓存 条数=9 名=豆包 场次=90      ← 栏位 A 里存着他的数据
[00:00:21] ★离开事件 人数=0                  ← 切观战（等于离开比赛）
[00:00:29] ★加入事件触发 人数=1 主机=豆包     ← 回来了，事件正常触发
[00:00:29] 缓存 条数=0 名=0 场次=0            ← 按 栏位(玩家) 读，读到空槽
[00:00:29] [存档] 场次 1                      ← 判成「新玩家」，场次 +1
```

同样的名字、同样的房间、10 秒间隔，只因为重进后栏位不同，缓存就没了。
**失效是静默的**：没有报错、没有日志，用户只看到「我的数据没了」。

## 正确做法

1. **键用名字，不用栏位**：每条缓存第一位存 `自定义字符串("{0}", 玩家)`，查找靠遍历比对名字。
   名字重连后不变（本模式实测两个上下文都能取到真名）。
2. **存二维数组**：`缓存 = [[名字, 数据1, 数据2, …], [...], …]`，整条写入 / 整条读取，
   不做偏移算数。工坊支持嵌套数组（`缓存[i][0]`），已实测。
3. **容量由代码定，不由栏位定**：元素数只跟规则写法有关，运行时存 8 条还是 40 条是同一份代码；
   别把「12 个栏位」当成容量上限。
4. **写入时机**：载入 / 成功那一刻立刻录一条，之后每次数据变化同步回同一条（按名字找）。
   **只写一次不够**——载入后新打的数据不刷新，重连会把进度退回到载入那一刻。
5. **重连判定**：`玩家加入比赛` 事件里只打标记（事件上下文里同类事件会被丢弃，名字也不一定拿得到），
   真正比对放 `持续 - 每名玩家` 里做。

## 什么时候 `栏位` 是合法的

`全局.某表[栏位(事件玩家)]` 这种**局内**用法没问题（语料里就有：把钱按栏位分开放、按栏位错开等待）。
判据只有一条：**这份数据要不要活过一次离开**。

- 不要（局内计数、冷却、临时目标）→ 栏位够用，且更快
- 要（存档码、余额、任务进度、战绩）→ 必须按名字存

## 静态检查能做的不多（设计如此）

「这条规则是不是在做跨重连缓存」是**设计判断**，语法上看不出来：同一份文件里
`全局.MoneySplit[栏位(事件玩家)]` 完全可能是正当的局内写法（真实语料 7 份里有 5 份用 `栏位`）。
所以这条不进校验器的必改项，只作为断言表里的一条常识（`docs/rules.tsv`「跨重连存档键」）。

## 怎么验

- 真机：单人进 12 人房 → 记下栏位和缓存条数 → 切观战 → 回到比赛 → 看缓存是否还在
  （判据是「名字还在、数据还在」；条数变 0 就是踩了这条）
- 数值：日志里 `缓存 条数` 前后不一致、`场次` 从 N 变回 1，都是同一个信号
