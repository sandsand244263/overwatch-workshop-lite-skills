# 校验器覆盖面（诚实清单）

> 校验器不是"万能"的。下表写清**现在查什么、不查什么**，免得误以为"通过 = 能导入"。

检查分三层：**格式层**（语法）→ **数据 ID 层**（名字还在不在当前版本）→ **类型层**（槽位 / 完整性 / 上限）。

## 事实表对账（`tools/audit_rules.py`，接在 `devcheck` 第 1 行）

`docs/rules.tsv` 的「检查」列不是备注，是校验器的开关之一，写法只有四种，写错 `devcheck` 第 1 行就红：

| 写法 | 含义 | 脚本查什么 |
|---|---|---|
| `不接` | 只写在文档里，校验器不管 | 「场景 + 关键词」里有 ≥2 个有区分度的词命中同一个 `check_*` 的 docstring → 报「疑似已接」（文档频率 >3 的词不算证据，防止把 23 条全报一遍） |
| `已接:check_xxx` | 由那个函数管 | `core.py` 里必须真有 `def check_xxx(` |
| `反例:xxx.ow` | 由表驱动提示管，**文件名就是开关名** | 文件在 `tools/probes/negative/`、`expect.tsv` 有那一行、名字在 `core.RULE_CHECKS` 里（三者缺一就是静默关掉） |
| `已接:未定` | 确认代码在管，但没落到具体函数 | 单列出来，不算失败 |

- 一条事实多个函数：逗号并列，例 `已接:check_setting_key_layers,已接:check_importer_verified,已接:check_setting_belongs`。
- 复核过的假阳性 / 部分覆盖写进 `tools/rules-audit-ack.tsv`（场景 / 命中函数 / 结论 / 理由 / 日期），脚本不再当失败报，`-v` 里仍会列出来——留痕，但不天天吵。
- 明细：`python tools/audit_rules.py -v`。反向清单（从没被点名的 `check_*`）也在这里输出，是补事实表的候选。

## 语义提示层（warning，出处就是 `docs/rules.tsv`）

不判错，只提醒「能导入但八成不是你想要的」。每条都能用 `python tools/ws.py rule <关键词>` 查到完整解释。

| 提示 | 触发 | 依据 |
|---|---|---|
| 事件规则里写了 `While(真)` | 非「持续」、非「子程序」的规则里出现 `While(真)` | E-50（忙时同类事件被丢弃） |
| 循环里只建 HUD 不删 | `While`/`For` 体里有 `创建HUD文本` 而没有 `消除HUD文本` | E-32（128 条并存上限） |
| 死斗里 `生成机器人(…, 队伍1/队伍2, …)` | 模式是自由混战，且队伍参数写 队伍1/队伍2 | E-49（死斗队伍栏位 0） |
| `创建效果` 参数少于 6 个 | 只有**实机验过「签名能省、引擎不收」**的元素才按语料下限当约束（当前只有 `创建效果`） | E-55（游戏报「之后应有';'」） |
| `持续 - 全局` 里把 `伤害` / `隐藏英雄HUD` / `开始镜头` 指向 `本地玩家` | 只认这三个动作 + 目标字面就是 `本地玩家` | E-50 五（对 本地玩家 无效；语料 197 处 `创建HUD文本(本地玩家,…)` 正常，故不扩到其它动作） |
| 循环少了 `End;`（`While`/`For` 个数 > `End;` 个数） | 只判必要条件，不逐层配对（真实语料里 `If … Else` 省 `End;` 有 22 处，属正常写法） | E-61（导入不报错，循环只执行一次） |

| 玩家槽塞数字 / 真假 | error | `设置移动速度 第 1 个参数 要的是「玩家」…这里填的是 100` |
| 数值槽塞玩家表达式 | error | `等待 第 1 个参数 要的是「数值」，这里填的是玩家表达式 所有玩家(所有队伍)` |
| `调用子程序(X)` 但 X 没声明 | error | `调用子程序(S_NotExist) 找不到对应的子程序声明` |
| 子程序事件 `子程序; X;` 但 X 没声明 | error | `事件里的子程序 X 找不到对应的子程序声明` |
| 子程序声明了从未被调用 | warning | `子程序 X 声明了但从未被调用` |
| 变量声明了从未赋值 | warning | `变量 X 声明了但从未赋值，会一直是 0`（认 `=` / `+=` / 数组下标赋值 / For 控制变量） |
| 数值参数写了 `%` 后缀（`%` 是取余运算符，`50%` 会报「之后应有一个值」） | error | `「%」在工坊里是取余运算符，后面必须跟数值…要写百分比就用纯数字：50 就是 50%` |
| 全局变量存了「本地玩家」的局部值（函数式 + 裸赋值两种写法） | error | `全局变量不能存局部值（含「本地玩家」）；游戏会报「局部值只能用于视觉效果或HUD动作」` |
| 单条规则 > 98KB（100352 字节） | error | `规则「…」有 N 字节，超过单条规则 98KB…拆成多条规则` |
| 预计元素数 > 32768 | error | `预计元素数约 N，超过 32768 上限` |
| 预计元素数 16384~32768 | warning | `已接近 32768 上限（估算不精确，仅提示）` |

类型检查**只报硬冲突**：玩家槽里的数字字面量、数值槽里的玩家表达式。
其余组合（布尔 / 选择 / 向量 / 变量槽）一律不报——数据里的类型标注不全，
历史上按「必填参数个数」硬查过一次，71 条噪声，整条撤回了。这次不重演。

> 元素数超限为什么是 error：元素估算**系统性低估**（真实 235KB 模式实测 16918 / 估算 7668，系数 2.12）。
> 估算值本身已超 32768 时，真实元素数一定远超上限，不存在虚警；
> 临界带（16384~32768）才只给 warning，因为那一带误差能翻转结论。

## 行号保真

`join_multiline_strings` / `merge_continuations` 会把跨行字符串和跨行语句挪到起始行，
**行号本身不变，但内容位置变了**。校验器用两张 `SegMap`（字符列 → 源行号）串起来，
报错统一换算回原文行号：

- 跨行语句第 3 行上的 `地图(万圣节艾兴瓦尔德)` 报**第 3 行**，不是语句开始的第 1 行
- 实测核对：`猪猪钩钩乐·天赋版.ow` 报出 13 处地图错误，与 `grep -n 万圣节` 的 13 行逐一相同

只能换算到"行"，不到"列"——校验器只输出行号。

## 判断原则

- **通过 ≠ 能导入**：校验器只覆盖"知道该怎么错"的部分
- **报错 ≠ 写错了**：先看文案，很多是"应该写成 X(...)"这类格式问题
- 遇到校验器没拦住、游戏却报错的，**先补反向用例，再修检查**（否则下次还会漏）

### 为什么索引 ≥26 的字母名不判

真实语料 `符文乱斗.ow`（他人作品，能导入运行）里 `玩家:` 段有 `77: S`、`78: E`，是游戏自己导出来的。
若按「字母名必须对上位号」一刀切，这个文件会平白多 2 条误报，且与「它能导入」矛盾。
所以判据收窄成：**名字是 A~Z 且索引落在内置区（0~25）却不是该字母的位号** → 撞内置变量。
用户踩的那条 `0: V`（V=21）正好落在这个区间。
