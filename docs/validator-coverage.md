# 校验器覆盖面（诚实清单）

> 校验器不是"万能"的。下表写清**现在查什么、不查什么**，免得误以为"通过 = 能导入"。

## 现在会查（error 级，直接拦住）

| # | 检查 | 典型报错 |
|---|---|---|
| 1 | 未知函数名 | `未知函数名：XXX（签名表里没有）` |
| 2 | 参数个数上下限 | `最多 2 个，实际 4 个` / `至少要 2 个` |
| 3 | **事件参数个数** | `事件「玩家造成最后一击」需要 2 个参数…只有 0 个` |
| 4 | **裸函数名**（该写 `X(...)`） | `「所有玩家」是函数，必须写成 所有玩家(...)` |
| 5 | 变量：未声明 / 声明未赋值 | `全局.X 没有在变量块里声明` |
| 6 | 设置块：结构、键名、值格式、布尔词 | `该键只能写 开启 / 关闭` |
| 7 | 块级结构：重复块、`}` 后多分号 | — |
| 8 | 元素数超限预警 | `接近 32768 上限` |

## 现在会查（warning 级，不拦但提示）

| # | 检查 | 说明 |
|---|---|---|
| 9 | 字符串插值缺值 | `模板里有 {1}，但只给了 1 个值` |
| 10 | 规则名重复 | 同名规则难排查 |
| 11 | 延迟取值快照 | `大字体信息` 里引用随后会被改写的变量 |
| 12 | 地图 id 为 0、变量名只差大小写、子程序调用无声明、块尾多分号 | — |

## 还不查（已知盲区）

| # | 盲区 | 后果 | 优先级 |
|---|---|---|---|
| A | **事件的第二个参数取值**（如写了 `三方;`） | 导入报错 | 中（要先拿到合法值表） |
| B | 下拉参数取值是否合法（部分） | 导入报错 | 中 |
| C | 变量类型不匹配（把玩家塞进数值槽） | 导入报错或行为异常 | 中 |
| D | 子程序参数个数 / 递归调用 | 报错 | 低 |
| E | 常量下标越界（`全局.arr[99]`） | 运行时读到 0 | 低 |
| F | 语义类：`持续` 规则不循环、`While` 无退出、HUD 数量上限 | **能导入但行为不对** | 高（但只能靠实测，见 `docs/pitfalls.md`） |

## 反向用例（防退化）

`tools/probes/negative/` 存"必须报错"的坏样本，清单在 `expect.tsv`。
`python tools/ws.py check-all` 会同时跑正样本（必须全过）和反向用例（必须报出预期错误）。

**只测正样本是不够的**——校验器最容易的退化方式，是"什么都放行"。

## 判断原则

- **通过 ≠ 能导入**：校验器只覆盖"知道该怎么错"的部分
- **报错 ≠ 写错了**：先看文案，很多是"应该写成 X(...)"这类格式问题
- 遇到校验器没拦住、游戏却报错的，**先补反向用例，再修检查**（否则下次还会漏）

| **动作写进条件里** | error | — |
| 事件参数取值 | warning | `三方;` → 不在已知取值（双方/全部/所有队伍/队伍1/队伍2） |

- 新增已覆盖项：动作/值互串（这是**最高频**的一类，之前完全没查）
