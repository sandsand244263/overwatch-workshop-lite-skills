# 校验器覆盖面（诚实清单）

> 校验器不是"万能"的。下表写清**现在查什么、不查什么**，免得误以为"通过 = 能导入"。

检查分三层：**格式层**（语法）→ **数据 ID 层**（名字还在不在当前版本）→ **类型层**（槽位 / 完整性 / 上限）。

## 现在会查（error 级，直接拦住）

| # | 检查 | 典型报错 |
|---|---|---|
| 1 | 未知函数名 | `未知函数名：XXX（签名表里没有）` |
| 2 | 参数个数上下限（`数组` / `自定义字符串` / `字符串` 是可变参数，不查上限） | `最多 2 个，实际 4 个` / `至少要 2 个` |
| 3 | 事件参数个数 | `事件「玩家造成最后一击」需要 2 个参数…只有 0 个` |
| 4 | 裸函数名（该写 `X(...)`） | `「所有玩家」是函数，必须写成 所有玩家(...)` |
| 5 | 变量：未声明 / 声明位段错 | `全局.X 没有在变量块里声明` |
| 6 | 设置块：结构、值格式、布尔词、枚举值 | `该键只能写 开启 / 关闭` |
| 7 | 块级结构：重复块、`}` 后多分号、尾逗号、缺分号、条件缺比较、`===` | — |
| 8 | 作用域：持续-全局规则里用 `事件玩家` | `「持续 - 全局」规则里不能用 事件玩家` |
| 9 | 值函数当动作 / 动作写进条件 | `「比赛结束」是值函数…不能单独当动作写` |

## 现在会查（warning 级，不拦但提示）

| # | 检查 | 说明 |
|---|---|---|
| 10 | 字符串插值缺值 | `模板里有 {1}，但只给了 1 个值` |
| 11 | 规则名重复 | 同名规则难排查 |
| 12 | 延迟取值快照 | `大字体信息` 里引用随后会被改写的变量 |
| 13 | 事件参数取值、地图 id 为 0、变量名只差大小写、子程序声明未调用、变量声明未赋值 | — |
| 14 | 元素数接近上限（16384~32768） | 估算不精确，只提示 |

## 数据 ID 层（error，对照 `data/` 当前版本表）

文案统一：`X「Y」不在当前版本数据表里（可能已改名或移除）`。

| 名字类别 | 出现在哪 | 对照的表 | 典型触发 |
|---|---|---|---|
| 地图名 | `地图(名字)` | `data/maps.tsv`（291） | 版本更新删掉的地图，如 `万圣节艾兴瓦尔德` |
| 英雄名 | `英雄(名字)` | `data/heroes.tsv`（54） | 英雄改名 / 新英雄写错字 |
| 技能名 | 英雄设置键里：`终极技能充能速度（鸡飞狗跳）` / `战斗时终极技能充能速度 鸡飞狗跳` | `data/abilities.tsv`（196 条 名字+英雄） | 技能中文名变了 |
| 按钮名 | `按钮(名字)` | `data/buttons.tsv`（10） | `按钮(技能三)` 这种 |
| 设置键 | 设置块里的 `键: 值` | `data/setting-keys.tsv`（757，模式/大厅/主程序/英雄页 并集） | 键改名（`急救包刷新时间` → `急救包刷新`） |
| 事件名 | 事件块第一行 | `data/events.tsv`（14） | 事件改名 |

生成方式：`python tools/gen_name_tables.py`（从 `hero-setting-names.tsv` / `ability-stats.tsv` /
`mode-pages.tsv` / `settings-pages.tsv` / `schema-keys.tsv` / `lobby-*` / `hero-*-keys` 汇总）。
**宁可多留不许少留**——名字表漏一个就是真文件上的误报（54 英雄 / 196 技能 / 757 键在 4 个真实模式上零误报）。

故意不查：`调用子程序(S_Menu_Open)` 这类子程序名、玩家变量与全局变量名——
它们不是上面六类，存在性由变量块 / 子程序块检查负责。

## 类型层（error / warning）

| 检查 | 级别 | 文案 |
|---|---|---|
| 玩家槽塞数字 / 真假 | error | `设置移动速度 第 1 个参数 要的是「玩家」…这里填的是 100` |
| 数值槽塞玩家表达式 | error | `等待 第 1 个参数 要的是「数值」，这里填的是玩家表达式 所有玩家(所有队伍)` |
| `调用子程序(X)` 但 X 没声明 | error | `调用子程序(S_NotExist) 找不到对应的子程序声明` |
| 子程序事件 `子程序; X;` 但 X 没声明 | error | `事件里的子程序 X 找不到对应的子程序声明` |
| 子程序声明了从未被调用 | warning | `子程序 X 声明了但从未被调用` |
| 变量声明了从未赋值 | warning | `变量 X 声明了但从未赋值，会一直是 0`（认 `=` / `+=` / 数组下标赋值 / For 控制变量） |
| 单条规则 > 98KB（100352 字节） | error | `规则「…」有 N 字节，超过单条规则 98KB…拆成多条规则` |
| 预计元素数 > 32768 | error | `预计元素数约 N，超过 32768 上限` |
| 预计元素数 16384~32768 | warning | `已接近 32768 上限（估算不精确，仅提示）` |

类型检查**只报硬冲突**：玩家槽里的数字字面量、数值槽里的玩家表达式。
其余组合（布尔 / 选择 / 向量 / 变量槽）一律不报——数据里的类型标注不全，
历史上按「必填参数个数」硬查过一次，71 条噪声，整条撤回了。这次不重演。

> 元素数超限为什么是 error：元素估算**系统性低估**（真实 235KB 模式实测 16918 / 估算 7668，系数 2.12）。
> 估算值本身已超 32768 时，真实元素数一定远超上限，不存在虚警；
> 临界带（16384~32768）才只给 warning，因为那一带误差能翻转结论。

## 行号保真

`join_multiline_strings` / `merge_continuations` 会把跨行字符串和跨行语句挪到起始行，
**行号本身不变，但内容位置变了**。校验器用两张 `SegMap`（字符列 → 源行号）串起来，
报错统一换算回原文行号：

- 跨行语句第 3 行上的 `地图(万圣节艾兴瓦尔德)` 报**第 3 行**，不是语句开始的第 1 行
- 实测核对：`猪猪钩钩乐·天赋版.ow` 报出 13 处地图错误，与 `grep -n 万圣节` 的 13 行逐一相同

只能换算到"行"，不到"列"——校验器只输出行号。

## 还不查（已知盲区）

| # | 盲区 | 后果 | 优先级 |
|---|---|---|---|
| A | 下拉 / `选择[…]` 参数的取值合法性（签名表里只抄了前几项） | 导入报错 | 中 |
| B | 向量 / 布尔 / 队伍槽位的类型冲突 | 导入报错 | 中 |
| C | 子程序参数个数、递归、子程序内事件上下文 | 报错 | 低 |
| D | 常量下标越界（`全局.arr[99]`） | 运行时读到 0 | 低 |
| E | 变量实际存的数据类型（工坊变量无类型） | 运行时逻辑错 | 低 |
| F | 技能名只查「括号内」「空格后」两种形态；`X冷却时间` 前缀式不拆 | 漏报 | 中（拆了容易误伤 `生命值` 这类非技能键） |
| G | 语义类：`持续` 规则不循环、`While` 无退出、HUD 数量上限 | **能导入但行为不对** | 高（只能靠实测，见 `docs/pitfalls.md`） |
| H | 元素数只是估算（系数 2.12），不等于游戏诊断面板真值 | 临界判断会偏 | 中 |
| I | 设置键只在「设置块里、且不在英雄块里」查；英雄块键走技能名检查 | 英雄块里的非技能键改名会漏 | 中 |

## 反向用例（防退化）

`tools/probes/negative/` 存"必须报错"的坏样本，清单在 `expect.tsv`（**16 个**）。
`python tools/ws.py check-all` 会同时跑正样本（必须全过）和反向用例（必须报出预期错误）。

**只测正样本是不够的**——校验器最容易的退化方式，是"什么都放行"。

| 用例 | 锁住的检查 |
|---|---|
| `old-map-name.ow` | 地图名 |
| `old-hero-name.ow` | 英雄名 |
| `old-ability-name.ow` | 技能名 |
| `unknown-button-name.ow` | 按钮名 |
| `unknown-setting-key.ow` | 设置键 |
| `unknown-event-name.ow` | 事件名 |
| `player-slot-number.ow` | 玩家槽类型 |
| `undefined-subroutine.ow` | 子程序完整性 |
| `rule-too-long.ow` | 单规则 98KB |
| `element-over-limit.ow` | 元素数上限 |
| `value-as-action.ow` / `bare-function.ow` / `event-missing-param.ow` / `event-player-in-global.ow` / `setting-out-of-range.ow` / `missing-var-block.ow` | 格式层 |

正样本 `tools/probes/name-tables.ow` 专门锁"合法名字不该报错"：英雄名、按钮名、技能名、
设置键、事件名、子程序声明+调用各走一遍。

## 判断原则

- **通过 ≠ 能导入**：校验器只覆盖"知道该怎么错"的部分
- **报错 ≠ 写错了**：先看文案，很多是"应该写成 X(...)"这类格式问题
- 遇到校验器没拦住、游戏却报错的，**先补反向用例，再修检查**（否则下次还会漏）

| 修复 | 之前 | 现在 |

## 2026-10-22 补：上限类检查与两个「默认关闭」的检查

**元素上限改用逆向模型**

`check_limits` 之前调 `element_count.estimate`（旧经验模型，235 KB 真实模式低估一半），现在用 `element_count2.estimate2`。否则「元素超 32768」这条检查在真实规模下几乎永不触发——这是会漏报的真 bug。

**新增但默认关闭（`ws.py check --strict` 才跑）**

| 检查 | 为什么默认关 |
|---|---|
| 下拉参数取值合法性 | `param-docs.tsv` 的 `index` 与真实参数位置对不上（实测 `创建HUD文本` 第 11 个参数应为「重新赋值」，数据里却是可见度），直接开会报 7 条假错误 |
| `持续` 规则没有 `While` / `While(真)` 无退出 | 原版 165 条规则里 94 条命中——大量初始化规则本来就只跑一次，属于正常写法。要区分「故意的单次执行」和「误用」，得先有语义标注，当前做不到 |

**结论**：误报比漏报更伤，这两条留作诊断工具，不进默认流程。等数据侧把参数序号对齐（重新从导出里带出 0-based index 与完整枚举）再考虑转正。

**做不了的**

| 想做的检查 | 卡在哪 |
|---|---|
| 独特英雄皮肤组合 ≤ 12 | `data/` 里没有皮肤清单，`皮肤` 只是一个 BOOL 设置键；无法从 .ow 反推皮肤组合数 |
| 不在玩家栏位的机器人上限 | 无对应设置键与数据 |

## 误报修复与自检（2026-10-22）

| 问题 | 修法 |
|---|---|
| `变量 X 声明了但从未赋值` 在真实模式上误报 2 条 | 赋值识别从「只认 `全局.X` / `事件玩家.X`」放宽到「任何 `.变量 =`」，覆盖 `全局.某玩家.变量 = …` 这种间接写法 |
| `core.py` 里同名函数定义了两份，后定义的静默生效 | `ws.py selftest` 扫描所有脚本的重复定义；`check-all` 前先跑 |

**教训**：Python 同名函数后定义的赢，改前面那份等于没改。写完检查函数先 `python tools/ws.py selftest`。

## 下拉值校验转正（2026-10-22）

**以前为什么关着**：`param-docs.tsv` 的参数序号与真实位置错位（例如 `创建HUD文本` 的第 11 个参数实测是「重新赋值」，表里标的是可见度），开着会刷假错误。

**现在**：直接用游戏数据的 `Parameters` 数组顺序，不再依赖那张表。

- 生成器：`tools/gen_param_options.py` → `data/param-options.tsv`
- 401 个元素 / 834 个参数，其中 **74 个带下拉选项**
- 检查：参数值必须是该参数的合法选项之一

实测结果：

| 文件 | 误报 |
|---|---|
| 65 个正样本 | 0 |
| 235 KB 真实模式（165 条规则） | 0（修掉「注释行里也算」之后） |

**踩到的坑**：第一版把注释里的 `// 修改全局变量(…, 事件玩家, …)` 也当代码查了。现在先 `strip_comments()` 再扫。

反向用例新增 `bad-dropdown.ow`（`修改全局变量(全局.X, 加法, 1)` → 只报「加法」这一处）。

## 报错给改法（2026-10-22）

`core.suggest(msg)` 给每条报错配一句「怎么改」，`ws.py check` 输出成 `→ 改法：…`。

- 覆盖：全部 30 条现有报错文案（反向用例实测 30/30）
- 做法：正则匹配报错文案 → 对应的修法；**匹配不上就不输出**，不硬编
- 例：

```
第 44 行 error：范围内玩家 的队伍参数不能写「双方」（那是事件筛选词）
     → 改法：改成 所有队伍（或 队伍1 / 队伍2）；「双方」只能用在事件行
```
