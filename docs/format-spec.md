# 格式规范（照这个写才导得进去）

基准文件：

- `golden3.ow` —— **实测能导入**的最小可用模式（设置块 + 变量 + 6 条规则），设置块优先照它抄
- `golden2.ow` —— 900 行复杂真实模式（子程序、数组、三元、跨行参数）
- `golden.ow` —— 早期样本，**设置块有非法键，只作结构参考**

## 一、文件骨架

```ow
设置
{
	主程序
	{
		模式名称: "模式名"
		描述: "说明"
	}

	大厅
	{
		比赛语音聊天: 启用
		观战者人数上限: 6
		返回大厅: 从不
	}

	模式
	{
		死斗
		{
			重装职责被动生命值加成: 禁用
		}

		综合
		{
			复生时间: 1%
			急救包刷新: 开启
			游戏模式开始: 即时
			英雄限制: 每队同一英雄最多2名
		}
	}

	英雄
	{
		综合
		{
			被动生命值恢复: 禁用

			路霸
			{
				伤害量: 10%
			}

			启用英雄
			{
				路霸
			}
		}
	}
}

变量
{
	全局:
		0: totalKills

	玩家:
		0: streak
		1: boostReady
}

规则("规则名")
{
	事件
	{
		持续 - 每名玩家;
		双方;
		全部;
	}

	条件
	{
		按钮被按下(事件玩家, 按钮(互动)) == 真;
	}

	动作
	{
		大字体信息(事件玩家, 自定义字符串("你好"));
	}
}
```

顺序固定：`设置` → `变量` → `子程序`（可选）→ 一条或多条 `规则`。

**块标题独占一行，`{` 在下一行**（VS Code 插件的语法定义就是这样匹配的）：

- `变量` 单独一行，`{` 下一行
- `子程序` 单独一行，`{` 下一行
- `规则("名字")` 单独一行，可带 `禁用 ` 前缀，`{` 下一行
- `事件` / `条件` / `动作` 各自单独一行，`{` 下一行

> **设置块不要手写，也不要照 `golden.ow` 抄。** 从 `golden2.ow`（900 行复杂模式）里整块复制再改值。`golden.ow` 的设置块里 `综合` 用了 `允许切换英雄`，实测导入报「`综合 {` 之后应有一个游戏模式设置」——那个键不属于 `综合`。实测有效的 `综合` 键只有 `复生时间` / `急救包刷新` / `游戏模式开始` / `英雄限制`。

## 二、变量块必须分两段

```ow
变量
{
	全局:
		0: totalKills

	玩家:
		0: streak
		1: boostReady
}
```

- 段标签带冒号：`全局:` / `玩家:`，变量声明缩进一层
- **两个段的索引各自从 0 开始**，互不影响
- 只写 `0: xxx` 不写段标签，会报「`变量 {` 之后应有 `全局`」
- 引用：全局写 `全局.名字`，玩家写 `事件玩家.名字` / `本地玩家.名字`

## 二·补、子程序块

```ow
子程序
{
	1: AITarget
	2: AIMove
	5: AIAttackLA
}
```

`索引: 子程序名`，索引可跳号，名字只能是英文。调用写 `调用子程序(子程序名);`。

## 二·补二、设置块的值不许自造

设置块的键和合法值都只能从 `golden.ow` / `golden2.ow` 里抄：

- `综合` 块**只认四个键**：`复生时间` / `急救包刷新` / `游戏模式开始` / `英雄限制`。放 `允许切换英雄`、`随机英雄复生` 会报「`综合 {` 之后应有一个游戏模式设置」——报错指块头，实际错在块里第一个键。这是一次真实导入验证过的结论（v1.4.0 的样本失败三次，v1.5.0 的模板一次通过）
- 工坊本身有枚举 bug：同一个概念在导出里可能显示成 `启用` / `开启` / `关闭` / `禁用`，但内部只认其中某一个。所以**设置块的值也不要改**，要改只改数字百分比
- 缩进用 Tab 或 4 个空格都行（VS Code 插件的官方测试文件用空格）
- `主程序` 里 `描述` 写在 `模式名称` 之前（`golden2.ow` 证据）
- 单个动作加 `禁用` 前缀可以留着不生效：`禁用 创建HUD文本(...);`

## 三、事件块：1 行或 3 行

```ow
事件
{
	持续 - 全局;
}
```

```ow
事件
{
	持续 - 每名玩家;
	双方;
	全部;
}
```

- 只有全局事件是 1 行；**其它所有事件必须 3 行**：事件类型 → 队伍过滤 → 英雄过滤
- 写 2 行会报错（overpy 解析器原话："either 1 (global) or 3 (every other event)"）
- 队伍过滤：`双方` / `队伍1` / `队伍2`；英雄过滤（第 3 行）：`全部` / `栏位 0`–`栏位 11` / 具体英雄名

## 四、控制流用英文关键字 + 分号

```ow
While(正在空中(事件玩家) == 真);
	施加推力(事件玩家, 上, 6, 至地图, 取消相反运动);
	If(按钮被按下(事件玩家, 按钮(蹲下)) == 真);
		施加推力(事件玩家, 下, 12, 至地图, 取消相反运动);
	Else If(按钮被按下(事件玩家, 按钮(跳跃)) == 真);
		施加推力(事件玩家, 上, 6, 至地图, 取消相反运动);
	End;
	等待(0.016, 无视条件);
End;
```

单行写法 `如条件为“真”则循环;` 也存在（`golden.ow` 里就在用），多分支一律 `If / Else If / End`。

## 五、硬规则

| # | 规则 | 细节 |
|---|---|---|
| 1 | 每条语句以 `;` 结尾 | 块收尾的 `}` 后面**不加**分号 |
| 2 | 设置块是 `键: 值` | 不是语句，不加分号；冒号半角 |
| 3 | 变量名只能是英文 | `[_a-zA-Z][_a-zA-Z0-9]*`：字母或下划线开头，**不能以数字开头**，≤ 32 字符；中文名必失败 |
| 4 | 字符串用英文双引号 | `"文本"`，内部引号写 `\"`；`\n` 可换行 |
| 5 | 参数用半角逗号分隔 | **不许尾逗号** |
| 6 | 条件块每行必须有比较运算 | `== != > < >= <=` |
| 7 | 注释只有 `//` 和 `/* */` | `#` 不是注释 |
| 8 | 没有 `===` | 赋值 `=`，比较 `==` |
| 9 | 参数个数不超过签名 | 见 `signatures.md`，尾部参数可省 |
| 10 | 「可见」参数填玩家 | 不是真假；常用 `事件玩家` / `本地玩家` / `所有玩家(所有队伍)` |
| 11 | 颜色写成 `颜色(x)` | 例如 `颜色(白色)`，不能裸写 `白色` |
| 12 | 空值写 `空` | HUD 的子标题/文本可以填 `空` |
| 13 | `持续 - 全局` 里不能用 `事件玩家` | 用 `本地玩家` |
| 14 | 长参数可以跨行续写 | 括号没闭合就继续，续行不要求分号 |
| 15 | 地图写 `名字 GUID` | 例如 `黑森林 972777519512063901` |
| 16 | **布尔项只能写 `开启` / `关闭`** | 游戏导出器写的是 `启用/禁用`，导入器不认（老 bug）。例：`允许切换英雄: 关闭` |
| 17 | **枚举项照抄原文** | 枚举的合法值可能就包含 `禁用`（如 `重装职责被动生命值加成: 禁用`），别一律改成关闭。全表见 `data/settings.tsv` |

## 六、生成时的查表顺序

1. 结构 → 本文件 + `golden.ow`
2. 参数个数与顺序 → `signatures.md`
3. 名字存不存在 → `actions.md` / `values.md` / `strings.md` / `enums.md`
4. 行为有没有 → `diagnostics.md` 的最小探针

## 七、常见导入报错对照

| 游戏报什么 | 多半是 |
|---|---|
| `变量 {` 之后应有 `全局` | 变量块缺 `全局:` / `玩家:` 段标签 |
| 应有一个关系运算子 | 条件没写比较运算 |
| 语法错误 / 意外的符号 | 尾逗号、缺分号、`===`、全角标点 |
| 参数数量不对 / 参数无效 | 参数个数超过签名 |
| 类型不匹配 | 可见位置填了 `真/假`，数值位置填了字符串 |
| 事件参数缺失 | 事件块写成 1 行，但这不是全局事件 |

## 设置块的实测规则（2026-10-21，实机导入成功）

这几条是连续 6 次导入失败换来的，按顺序看：

**1. 结构：模式下面只放一个块**

```ow
设置
{
	模式
	{
		死斗
		{
			键: 值
			…
		}
	}
}
```

不要在 `模式` 里再写 `综合` / `英雄` 子块——`英雄` 块会被拒（「之后应有一个游戏模式设置」）。块归属本身是自由的：只要键属于该模式的 schema 并集，写在哪个块都行。

**2. 数值：FLOAT 用百分比**

| 数据里 | `.ow` 里 |
|---|---|
| 1.0 | `100%` |
| 0.15 | `15%` |
| 0 | `0%` |

写 `0.1` 会被拒，且报错和「键不合法」一模一样（都是「之后应有一个游戏模式设置」）。

**3. 布尔：写 `开启` / `关闭`**

数据里是 `开启/禁用`（部分键是 `启用/禁用`、`是/否`），文件里统一写 `开启/关闭`。

**4. 默认值可以写也可以不写**

游戏导出时会省略默认项，但显式写出来也能导入（K 文件里 `主动复生: 开启` 就是默认值）。

**5. 键序不影响导入**

两份成功样本恰好是码位升序，但数据里 71/125 页并非升序——排序不是硬要求，按序输出只是习惯。

### 导入后再导出：游戏会怎么改写（2026-10-21 实测）

把单块文件导入成功后，再从工坊复制出来，结构变成了：

```ow
模式
{
	死斗                    ← 无花括号，单行
	综合
	{
		允许切换英雄: 开启
		…
	}
}
```

三条结论：

1. **块归属自由被反向证实**：我们全塞在 `死斗` 块里的键，游戏重新导出时全部归到 `综合` 块，导入时同样被接受
2. **无条目的模式写成裸名字**：`死斗` 后面没有花括号——这和无参数模式（`赏金猎手`、`死斗`）的写法一致
3. **等于默认值的键会被省略**：`主动复生: 开启`、`威能充能速度: 100%`、`追赶等级时造成消灭威能加值: 15%` 在导出里都消失了，因为它们就是默认值

所以生成端不必追求和导出结构一模一样：**导入只看键名与值，块结构宽松**。

## 设置块的完整子结构（全部来自实机导入成功的样本）

### 主程序

```ow
设置
{
	主程序
	{
		描述: "击杀计分 + 3连杀奖励"
		模式名称: "击杀连杀演练"
	}
}
```

`描述` 与 `模式名称` 的值是**带双引号的字符串**，不是 `自定义字符串(...)`。

### 大厅

```ow
	大厅
	{
		地图轮换: 完成比赛后
		比赛结束后转换队伍: 否
		观战者人数上限: 6
		返回大厅: 从不
		队列中的玩家可以加入: 是
		最低延迟（毫秒）: 100000000
		比赛语音聊天: 启用
		玩家上限 队伍1: 4
		玩家上限 队伍2: 4
		玩家断线时暂停游戏: 是
		自由混战人数上限: 10
		队伍平衡: 攻防轮换后
	}
```

注意：`玩家上限 队伍1/队伍2` 之间是**半角空格**；键的完整清单见 `data/lobby-keys.tsv`。

### 模式

```ow
	模式
	{
		死斗
		{
			获胜得分: 1
		}

		综合
		{
			允许切换英雄: 关闭
		}

		禁用 攻击护送
		{
			职责限制: 1重装，2输出，2支援
		}
	}
```

- 被禁用的模式写成 `禁用 模式名`
- **无内容的模式写成裸名字**，后面不带花括号（如 `赏金猎手`、`死斗`）
- `职责限制` 的值用**全角逗号**分隔：`1重装，2输出，2支援`

### 地图

```ow
	模式
	{
		死斗
		{
			启用地图
			{
				地图工坊室内 972777519512064577
			}
		}
	}
```

地图名和 GUID 之间是**半角空格**，GUID 用 `data/maps.tsv` 查。

### 英雄级（实测正确结构）

```ow
	英雄
	{
		综合
		{
			死神
			{
				伤害量: 150%
				被动生命值恢复: 关闭
			}
		}
	}
```

**两层包装是必须的**：`英雄` → `综合` → `英雄名` → 键。
- 少了 `综合` 那层会报「之后应有一个队伍设置」
- `英雄` 与 `模式` 同级
- 导出文件里有时会写成 `英雄 { 综合 {…} D.Mon {…} }`（英雄名与综合平级）——**那种写法是导出的简化形式，不保证能再导入**

### ⚠️ 导出不可当规范（两次踩坑）

1. **导出会省略默认值**：`主动复生: 开启`、`威能充能速度: 100%` 这类等于默认的项不会出现在导出里
2. **导出会写错布尔词**：已知 bug——`被动生命值恢复` 导出成 `禁用` 或 `启用`，而导入只认 `关闭` / `开启`。
   官方导出→直接导入会失败，必须手动改词。作者自己在发布地图前也要手工检查这一项。
3. **导出会简化块结构**：多块会被归一化，`英雄` 下可能省略 `综合` 层

结论：**样本用来学写法，规范以实机导入成功为准。**

### 数值单位

| 类型 | 写法 |
|---|---|
| 百分比类（伤害量、复生时间、威能充能速度） | `150%` / `100%` / `0%` |
| 整数类（获胜得分、比赛时长、观战者人数） | 直接写数字 |
| 时间类（比赛时长（分钟）） | 直接写数字，单位在键名里 |

## 英雄设置键名的拼装规则（已逆向，261 条真实导出验证）

**规则一句话**：键名 = `TextFormat` 里的 `%1$s` 换成技能名 → **删掉 ASCII 的 `(` `)`**（全角 `（）` 和空格原样保留）。

| 模板原文 | 技能名 | 最终键名 |
|---|---|---|
| `终极技能充能速度（%1$s）` | 死亡绽放 | `终极技能充能速度（死亡绽放）` |
| `战斗时终极技能充能速度 (%1$s)` | 死亡绽放 | `战斗时终极技能充能速度 死亡绽放` |
| `%1$s冷却时间` | 幽灵形态 | `幽灵形态冷却时间` |
| （模板与名字都空） | 幽灵形态 | `幽灵形态` |

**为什么会有三种写法**：数据里全角括号和半角括号本身就共存，writer 只剥掉半角 → 半角那组退化成「空格 + 参数」。

**验证强度**：`golden.ow` 9 条 + `golden2.ow` 252 条真实英雄键，共 **261/261 零漏**，跨英雄交叉命中（安燃 `战斗时终极技能充能速度 朱羽焚`、路霸 `链钩冷却时间`、D.Mon `助推器充能速度`）。

**数据表**：`data/hero-setting-names.tsv`（54 英雄 / 1752 行），`ws.py settings --hero <英雄>` 直接用它生成。

**两个反直觉的点**
- `IsHiddenAbility` 为真的技能**不能排除**：D.Va 的 `微型飞弹冷却时间`、破坏球的 `感应护盾冷却时间` 都标了 hidden 但真实存在
- 威能（Perks）技能本来就不在 Loadouts 与 Perks 的交集里，不影响键名生成

### 界面显示名 ≠ `.ow` 键名（重要）

同一个设置项，游戏界面显示的写法和 `.ow` 里写的可能不同：

| 界面显示 | `.ow` 键名 |
|---|---|
| `战斗时终极技能充能速度（死亡绽放）` | `战斗时终极技能充能速度 死亡绽放` |
| `终极技能自动充能速度（死亡绽放）` | `终极技能自动充能速度 死亡绽放` |
| `终极技能充能速度（死亡绽放）` | `终极技能充能速度（死亡绽放）`（一致） |

规律：导出器会把**半角括号** `(` `)` 删掉，全角 `（）` 和空格保留。所以界面看到的全角括号，在 `.ow` 里可能是空格。

**生成 `.ow` 时一律用 `.ow` 那一列**；抄界面名字容易导入失败。
