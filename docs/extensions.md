# 工坊扩展（编辑扩展）系统

扩展是「设置」里和 `地图工坊` 同级的一个块，用来解锁额外的效果/声音/弹道选项，代价是占用**扩展点数**，并**压低皮肤组合上限**。

## 一、.ow 里的写法

```ow
设置
{
	模式 { … }

	英雄 { … }

	地图工坊
	{
		鸣谢：为本模式提供建议的深度玩家们（不分先后）：: [7]
	}

	扩展
	{
		增益状态效果
		能量爆炸效果
		生成更多机器人
		弹道
	}
}
```

- 块内一行一个扩展名，**不带冒号、不带值**
- 不写这个块 = 一个扩展都没开
- 名字必须与 `data/extensions.tsv` 完全一致（错一个字游戏报「无法识别的扩展」或不生效）

## 二、11 个扩展与成本（`data/extensions.tsv`）

| 扩展 | 点数 | 解锁选项数 |
|---|---|---|
| 光束声音 | 1 | 14 |
| 播放更多效果 | 1 | 0 |
| 光束效果 | 2 | 17 |
| 减益状态效果 | 2 | 13 |
| 增益效果和减益效果声音 | 2 | 22 |
| 增益状态效果 | 2 | 16 |
| 爆炸声音 | 2 | 80 |
| 生成更多机器人 | 2 | 0 |
| 弹道 | 4 | 19 |
| 能量爆炸效果 | 4 | 40 |
| 运动爆炸效果 | 4 | 40 |

全部开满 = **26 点**。解锁关系共 261 条，存在 `data/extension-values.tsv`（扩展 → 下拉 ID → 选项名）。

## 三、点数规则

| 项 | 值 | 来源 |
|---|---|---|
| 基础可用点数 | **8** | 面板「可用扩展点数」 |
| 可用点数怎么增加 | 移除非游玩栏位、或禁用所有非地图工坊地图 | 面板原文 |
| 已用点数 | 已启用扩展的成本之和 | 面板「已扩展点数」实测：3 个扩展 1+2+2=5 时显示 7（含另两项） |
| 超限报错 | **已用扩展点数不能超过可用扩展点数**（确认按钮变灰） | 截图实测 |

**注意**：可用点数不是固定 8。`golden2.ow` 里开了 12 点的扩展——那个模式的作者移除了玩家栏位。所以**不能只按 8 判断超限**，校验器只报「已用多少 + 基础可用 8」，不当错误。

## 四、扩展带来的两个上限变化

| 上限 | 默认 | 变化规则 |
|---|---|---|
| 不在玩家栏位中的机器人最大数量 | **2** | 启用「生成更多机器人」→ **14** |
| 独特英雄皮肤组合最大数量 | **12** | 随已用点数下降 |

**皮肤上限的推导**（4 个干净样本 + 1 个报错态）：

| 已用点数 | 面板显示皮肤上限 |
|---|---|
| 0 | 12 |
| 2 | 11 |
| 3 | 11 |
| 7 | 10 |
| 10（超限报错态） | 10 |

拟合结果：**12 − ceil(已用点数 / 4)**

- 0 → 12 ✓
- 2 → 11 ✓
- 3 → 11 ✓
- 7 → 10 ✓
- 10 → 应为 9，实际显示 10（该状态已报「已用不能超过可用」，数值可能是异常态）

**这条是推定，不是实测确认**。要坐实，需要在一个干净状态（已用 ≤ 可用）下再取两个点：例如只开「弹道」（4 点）看是否为 11，或开「弹道 + 光束效果」（6 点）看是否为 10。

## 五、校验器做什么

| 检查 | 级别 | 说明 |
|---|---|---|
| 扩展名是否存在 | error | 拼错时游戏只报「无法识别」，不给候选 |
| 已用点数 + 派生上限 | warning | 报「已用 N（基础可用 8）；机器人上限 X；皮肤上限约 Y（推定）」 |
| 用了扩展专属选项但没开扩展 | error | 依赖 `data/extension-values.tsv`（261 条），只对**基础游戏里不存在**的选项名判定，避免误报 |

**不做的**：不判断「已用 > 可用」为错误——可用点数取决于大厅设置，静态算不出来。

## 六、数据来源与重生成

```bash
python tools/gen_extensions.py            # 从 workshop_zhCN.json 重新生成
```

`workshop_zhCN.json` 的 `Extensions` 段带 `Cost` 与 `UnlockedValues`，是这次能一次拿全 11 个扩展成本与 261 条解锁关系的原因。

## 七、修正（2026-10-22 第二轮实测）

用户提供第二组面板数据后，先前的「皮肤 12−ceil(已用/4)」模型被推翻：

| 大厅配置 | 可用点数 | 已用点数 | 皮肤上限 | 机器人上限 |
|---|---|---|---|---|
| 多模式 + 多地图 | 8 | 0 | 12 | 2 |
| 多模式 + 多地图 | 8 | 2 | 11 | 2 |
| 多模式 + 多地图 | 8 | 7 | 10 | 2 |
| **单模式（死斗）+ 单地图（工坊室内）** | **16** | 4 | **15** | **0** |

两个被推翻的假设：

1. **「机器人上限默认 2」错** —— 单模式单地图时是 **0**。它跟大厅配置走，不是固定值。
2. **「皮肤上限只由已用点数决定」错** —— 可用点数从 8 变 16 时（换大厅配置），皮肤上限整体上移。

**现在的做法**：校验器只报「已用扩展点数 N」，明确写出可用点数取决于大厅设置、皮肤与机器人上限请以面板为准。**不再输出推算数字**——算不准的数字比不报更糟。

**要拿到公式，需要一次受控扫描**：固定大厅，只改勾选（0 / 1 / 4 / 8 点各看一次面板），再换一个大厅变量（模式数或地图数）重复一次。两组数据才能分离「可用点数」与「已用点数」各自对上限的影响。
