# 避坑：语法与写法

> 字符串、队伍参数、变量赋值、子程序、数组下标等写法规则。

> 总索引见 [pitfalls.md](./pitfalls.md)；报错原文查 [errors.md](./errors.md)。

## HUD 的正确写法（实测 2026-10-20）

- **HUD 文本里的变量引用自动刷新**：`创建HUD文本(…, 自定义字符串("{0}", 全局.totalKills), …)` 建一次即可，数字会跟着变量变，**不要重复创建**
- 重复创建会堆叠：每条都会新增一行（实测 4 次击杀 → 4 行 HUD，虽然每行显示的都是最新值）
- 刷新槽的具体取值对"是否堆叠"没有影响
- `持续` 规则只执行一次，所以变量自增要靠**事件**（击杀、按键、受伤）或 `While(真)` + `等待`，不能指望规则自己跑第二遍
- 结论模板：HUD 建一次 + 变量由事件维护 = 活数字；不要用循环刷 HUD

## 设置块（实测 2026-10-20）

- `模式 > 综合` 实测能放 **7 个键**：`允许切换英雄` / `复生时间` / `急救包刷新` / `游戏模式开始` / `英雄限制` / `重装职责被动生命值加成` / `随机英雄复生`
- 早期认为"综合只认 4 个键"是**误判**：真正报错原因是 `允许切换英雄: 禁用` 用了导出器的老词，正确写法是 `关闭`
- **死斗模式没有 `玩家上限 队伍1/队伍2`**，团队模式才有——套模板时要按模式类型选
- 设置块只能整块照抄实测通过的样本（`tools/probes/_setup_template.txt`），不要手拼层级

## 数组下标从 0 开始（实测 2026-10-21）

```ow
设置全局变量(g, 数组(10, 20, 30));
// 实测结果（查看器）：
//   数组值的索引(全局.g, 10) = 0     ← 不是 1
//   数组值的索引(全局.g, 20) = 1
//   数组值的索引(全局.g, 30) = 2
//   数组值的索引(全局.g, 99) = -1    ← 找不到返回 -1（官方说明也这么写）
```

**坑在哪**：绝大多数语言直觉是"第一个元素是 1 号"，工坊里是 **0 号**。

- 取第一个元素：`全局.g[0]`
- 遍历 N 个元素：`For(i, 0, N - 1, 1)`，或 `For(i, 0, N, 1)` 靠"不含终止值"自然停在 N-1
- 判断"有没有找到"：结果 `== -1` 就是没找到，不要写 `== 0`

**注意别和 `For` 混淆**：`For(i,1,5,1)` 是从 1 数到 4（不含 5）；数组下标却是从 0 起。两者方向相反，写循环取值时最易错。

## 队伍参数不能写「双方」（2026-10-22 实测）

```ow
范围内玩家(眼睛位置(事件玩家), 8, 双方, 关闭)     ❌
范围内玩家(眼睛位置(事件玩家), 8, 所有队伍, 关闭)   ✅
```

游戏报的是 **「第 44 行的"8,"之后应有一个值」**——指向的是半径那个数字，原因是它没能把「双方」认成合法队伍值，于是认为参数还没给完。

「双方」只用于**事件筛选**（`玩家造成最后一击; 双方; 全部;`）。队伍类参数用 `所有队伍` / `队伍1` / `队伍2`。

校验器现在会直接拦：`范围内玩家 的队伍参数不能写「双方」（那是事件筛选词）`。

## 字符串作参数必须包成 自定义字符串（2026-10-22 实测）

```ow
记入查看器("开始测试");                    ❌ 报「"记入查看器("之后应有一个值」
记入查看器(自定义字符串("开始测试"));        ✅
```

`.ow` 里没有"裸字符串"这种值——所有文本都要写成 `自定义字符串("…")`（或 `字符串("…")`）。

例外：**单独一行的 `"注释"` 是合法的**（那是字符串注释），不受影响。

校验器现在会拦：`记入查看器 的参数里不能直接写字符串，要包成 自定义字符串("…")`。

## 变量和子程序有「默认存在」的那一批（2026-10-22 用户指出）

| 对象 | 默认存在 | 索引 |
|---|---|---|
| 全局变量 | **A~Z 共 26 个** | 0~25 |
| 玩家变量 | **A~Z 共 26 个** | 0~25 |
| 子程序 | **Sub0~Sub7 共 8 个** | 0~7 |

也就是说 `全局.V`、`全局.P`、`调用子程序(Sub3)` **不写 `变量` / `子程序` 块也是合法的**。

只有超出这批的变量才需要在块里声明。校验器据此放过单字母大写变量名与 `Sub0~Sub7`。

> 之前把 `全局.V` 判成「未声明」，是我漏了这条常识。

## 设置键的「层」是权威数据，不用实测推导（2026-10-22）

`ruleset_schemas.json` 里 32 个 schema 的 Entries 就是归属表，`tools/gen_setting_schemas.py`
生成 `data/setting-schemas.tsv`（474 行 / 268 个键）。

- 层的名字就是块名：`综合` / `决斗先锋` / `英雄` / `武器` / `死斗` …
- `复生时间` 属于「英雄」层；`决斗先锋` 里对应的是 `复生时间倍率`（差两个字，极易混）
- 校验器现在会提示「该键属于 X 层，这里写在 Y 里」

**注意**：恰好同名的键可能属于多个层（`复生时间` 在「英雄」和「决斗先锋」都有），所以这条是 warning。

## 子程序不是「函数体」，是一张索引表（2026-10-22 实测纠正）

```ow
子程序
{
	1: set_button_support
	2: set_bothero
}
```

**块里只写 `索引: 名字`，没有函数体。** 函数体写在普通规则里，事件固定两行：

```ow
规则("设置按钮支持")
{
	事件
	{
		子程序;
		set_button_support;
	}

	动作
	{
		…
	}
}
```

调用：`调用子程序(set_button_support);`

之前文档写成 `子程序 { 名字 { 动作 { … } } }`，是错的。

## 变量不能裸写赋值（2026-10-22 实测）

```ow
i = 1;              ← 错，游戏报「'1);' 之后应有一个值」
事件玩家.i = 1;      ← 玩家变量
全局.i = 1;          ← 全局变量
```

`For 玩家变量(事件玩家, i, …)` 里的循环变量也一样，体内赋值必须带前缀。
校验器已加检查：裸变量名赋值 → error，并说明该写哪一种前缀。

## 内置字母变量本来就在，别为它写声明（2026-10-24 用户实机）

```ow
变量
{
	全局:
		0: V          ← 错：游戏报「错误：全局变量"V"与另一个变量冲突」
}
```

`V` 是内置变量，按字母表占 **第 21 号**（A=0、B=1 … V=21）。把它绑到 0 号就撞上了。
把这段声明整段删掉、规则里照写 `全局.V`，**导入正常**。

| 想用 | 怎么写 |
|---|---|
| A~Z 这些内置变量 | 直接用 `全局.A` / `玩家.A`，**不要声明** |
| 自己起名字 | 声明时字母与索引必须一致：`0: A`、`1: B`…；换名字就换没被占用的索引 |
| 数量超过 26 个 | 继续往下编号声明（内置只有 A~Z 这一批） |

**校验器现状**：目前 `check` 对「没有变量块却用 `全局.V`」还会报必改 —— **这是误报**（游戏照样导入），
已登记待修（`docs/rules.tsv` 的「变量声明」一条，依据 E-58）。

## 变量类动作的变量槽写「裸名」，不带前缀（2026-10-24 用户实机）

```ow
修改全局变量(全局.A, 添加至数组, 3);      ← 错，导入报错
修改全局变量(A, 添加至数组, 3);           ← 对
修改玩家变量(事件玩家, 子弹, 添加至数组, 被攻击方);
```

`修改全局变量` / `修改玩家变量` / `在索引处设置玩家变量` 这几个动作的变量槽，
写的是**变量名本身**（裸名），不是 `全局.A` 这种引用。九份真实语料里全是裸名写法。

注意这跟**赋值**相反：`全局.A = 3` 才是带前缀的。
**校验器现状**：`check` 目前放过 `全局.A` 写法 —— 漏报，会整文件导入失败，待修（`docs/rules.tsv` 对应一条，依据 E-59）。
