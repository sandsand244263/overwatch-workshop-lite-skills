# 工坊省元素审查规则

这份说明不是“语法手册”，而是审查和压缩时的快速判断规则。

## 使用顺序

审查一个工坊文件时，先按这个顺序看：

1. 先看是不是堆了太多 `HUD / 效果 / 地图文本`
2. 再看是不是堆了太多 `If / Else / While / For / 子程序`
3. 再看是不是用了很多 `过滤 / 排序 / 大数组 / 长字符串`
4. 最后才看零碎值能不能再抠

原因很简单：

- 真正吃元素的大头，通常不是单个轻量值
- 更常见的是显示层、结构层、过滤排序层

## 审查时优先保留什么

这些通常不值得为了省元素而过度折腾：

- `事件玩家`
- `真 / 假 / 空`
- `眼睛位置(事件玩家)`
- `所选位置(事件玩家)`
- `面朝方向(事件玩家)`
- `速度(事件玩家)`
- `英雄(...)`
- `按键(...)`
- `修改全局变量(..., 加, ...)`
- `修改玩家变量(..., 加, ...)`
- `等待(0.016, 无视条件)`
- `传送(...)`
- `设置状态(...)`

这些都已经测到很轻，很多是 `+0` 或负差值。

## 审查时优先压什么

这些通常更值得先动：

### 1. HUD 和效果

优先看这些：

- `创建HUD文本`
- `创建效果`
- `创建地图文本`
- 连续多条 `小字体信息`

原因：

- `创建HUD文本` 很贵
- `创建效果` 很贵
- 文本和效果一旦多人、多处、多次刷新，元素很容易爆

### 2. 复杂结构

优先看这些：

- 很多条小规则
- 很多 `If / Else`
- 很多 `While`
- 很多 `For`
- 很多子程序

原因：

- 结构本身就要吃元素
- 一旦每条结构里面再塞值、条件、行动，成本会叠上去

### 3. 过滤和排序

优先看这些：

- `已过滤的数组(...)`
- `已排序的数组(...)`
- 尤其是 `当前数组元素[字段]` 这种排序键

原因：

- 过滤本身就不便宜
- 字段排序很贵
- 这些通常比直观写法更容易“偷偷吃元素”

### 4. 大数组和长字符串

优先看这些：

- `数组(...)` 很长
- `自定义字符串(...)` 插值很多
- 一段逻辑里反复新建同样的数组或字符串

原因：

- 这两类增长很稳定
- 很容易在没感觉的情况下越堆越多

## 常用判断规则

### 规则 1

如果一个优化方案只是把 `0` 换成 `真 / 假 / 空 / 事件玩家 / 当前数组元素 / 当前数组索引` 这种轻量值，通常是赚的。

### 规则 2

如果一个优化方案新增了：

- `创建HUD文本`
- `创建效果`
- `已排序的数组(..., 当前数组元素[0])`
- `For`

那就要高度怀疑它虽然“看起来更高级”，但元素可能更贵。

### 规则 3

能直接改值，就先别改结构。

比如：

- 少一层 `If / Else`
- 少一条规则
- 少一个子程序

通常比抠单个轻量值更有效。

### 规则 4

能复用现成轻量值，就别重复包装。

例如：

- 已经有 `事件玩家`，就别再为了“统一格式”额外包一层没必要的表达式
- 已经能直接用 `所选位置`、`眼睛位置`、`速度`，就别先映射再取

### 规则 5

过滤和排序要特别谨慎。

如果只是想：

- 判断有没有
- 找一个简单目标
- 判断数量是不是大于 0

优先先想更短的直接写法，不要先默认上 `已过滤的数组` 或 `已排序的数组`

## 具体替代思路

### 少 HUD

如果只是临时提示，不一定非要上 `创建HUD文本`。
可以先考虑：

- `小字体信息`
- 复用已有 HUD
- 少颜色刷新、少字符串刷新

### 少效果

如果只是装饰，不要先上常驻 `创建效果`。
先考虑：

- 能不能不显示
- 能不能减少数量
- 能不能改成一次性 `播放效果`

### 少规则

如果两条规则只差一点点：

- 先考虑能不能合并条件
- 能不能用一个轻量分支解决

### 少分支

如果只是两种很接近的处理：

- 先想能不能改成更短的比较式
- 能不能改成一个值表达式

### 少排序

如果只是取最简单的目标：

- 先想能不能不用 `已排序的数组`
- 能不能先过滤后直接取首个
- 能不能把目标信息预先缓存

## 审查输出建议

以后做“省元素审查”时，优先按下面格式输出：

1. 先点出最贵的结构
2. 再点出最贵的显示层
3. 再点出过滤/排序问题
4. 最后再说零碎值替换

这样更符合真实收益。

## 已知限制

1. 这些结果是“按当前测试模板测出来的相对成本”，不是暴雪官方公开常量表。
2. 不同基准组之间不能直接拿差值横向硬比。
3. 有些动作名、枚举名、位置值写法曾经在测试过程中修正过，正式引用时以最终可导入版本为准。
