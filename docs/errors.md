# 报错对照手册（报错文案全集）

游戏报错只给一句话，不给原因，行号经常指向上一行。这一页是**报错文案全集的可读版**：
原句取自游戏本地化表（CASC `0x07C`，zhCN），分类、真因、改法、能不能提前拦住是我们加的注解。

> 机器版：`data/errors-full.tsv`（136 条），由 `python tools/gen_errors.py` 生成，可重复跑（两次 md5 一致）。
> 本页只做分类与注解，**原文一字不改**。

**档位纪律：B/C 档只做报错翻译，不做判据；检查规则只许引用 A 档。**
（A 档＝解析器级、exe 里有引用点；B 档 12 条 exe 无引用点；C 档 16 条是导入界面文案。
 `gen_errors.py` 已断言：`断言引用` 非「无」的行，`层` 必须是 A。）

## 0. 先读这三条

1. **原文是模板，不是成品句子。** 匹配时按模板归一，别整句比对：
   `%1$s` 期望的东西 / `%2$s` 实际写到的记号 / `%3$s` 行号。
   三个槽齐全的只有 `51129` 一条；绝大多数是「行号 + 实际记号」两槽；变量/子程序那族只有「名字」一槽。判不出的槽在表里写「未知」。
2. **行号会骗人。** 游戏报的行常是上一行或下一个符号的位置。先 `ws.py check` 定位，再回来看报错。
3. **「能提前报」是三档，不是二档。** 能 / 部分 / 不能，说的是现在 `ws.py check` 的水平；「能」也不等于改完就一定能导入。

## 0.0 一条命令直接问（`ws.py locate`）

贴进来的报错原文太长、槽位太绕时，别自己比对，直接跑：

```bash
python tools/ws.py locate "错误：第1184行的“0.350,”之后应有一个选项" --file 模式.ow
```

它做四件事，全部离线、可复现：

1. 在 136 条模板里挑出最像的那条（剥掉「错误：」前缀、引号、「的」再比；纯槽位模板压到最后，不抢位置）
2. 把槽位翻成人话——哪个是期望的记号、哪个是实际写到的、哪个是行号
3. 给「真因 + 改法 + 本地能不能提前报」（就是下面各条的注解）
4. 给了 `--file` 就指到**第几行**：打印上下文、标出报错行；报错停在块头上时，列出块里接下来 3 个键让你挑真错处；再跑一遍本地校验器，看它是不是也报了同一处

它**不做什么**：不猜你没给的读数、不替你改文件。行号对不上（文件导入后被改过）会明说，不硬指。

回归：`python tools/ws.py selftest` 里有 7 条写死的用例（`tools/probes/lab/locate/cases.tsv`），
覆盖键值行直指 / 块头跨行 / 缺分号 / 设置选项 / 无行号 / 行号越界 / 历史抄写变形。

### 深挖：这一族里最常踩的五种

**（1）「之后应有';'」= 参数写少了（`51129`，`%1$s` 是 `;`）**

签名里尾部参数写着「可以省略」，**游戏不一定认**。

```
✗ 创建效果(…, 球体, 颜色(白色), 矢量(0,3,0), 5)          ← 5 个参数
✓ 创建效果(…, 球体, 颜色(白色), 矢量(0,3,0), 5, 可见)     ← 6 个
```

真实语料里 `创建效果` 出现几十次，**最小也是 6 个参数**。`ws.py check` 会提示「创建效果 这里写了 5 个参数，语料里最少写 6 个」（`E-55`）。
通用做法：**语料里怎么写就怎么写，不要按签名省参数。**

**（2）「之后应有';'」也可能是值函数名不存在（`51129`，`%1$s` 是名字的一部分）**

```
✗ 全局.g4 = 上一个效果ID;      ← 没有这个函数
✓ 全局.g4 = 上一个文本ID;
✓ 全局.g4 = 数量(最后创建的实体());
```

数据表里带「上一个」的无参值函数只有：`上一个文本ID`、`上一个伤害调整ID`、`上一个治疗调整ID`、
`上一个助攻ID`、`上一个持续伤害效果ID`、`上一个持续治疗效果ID`。
写错名字游戏只会说「"上"之后应有';'」，指不到根因。`ws.py check` 现在直接报「值函数「X」不存在」并列出相近名字。

**（3）「之后应有一个值」有好几种完全不同的原因**

`51156` 说的是"这个位置要一个值表达式"，但玩家实际踩到的是：

| 写法 | 真正原因 | 怎么改 |
|---|---|---|
| `玩家数量(全部)` | `全部` / `双方` 是**事件块的选择器词**，不是队伍值。队伍参数只认 `所有队伍` / `队伍1` / `队伍2` | 死斗里数人用 `数量(所有玩家(所有队伍))`；按队取用 `队伍1` / `队伍2` |
| `生成机器人(死神, 队伍1, …)` | 英雄参数必须包 `英雄(…)` | `生成机器人(英雄(死神), 队伍1, -1, 空, 空)` |
| `记入查看器("[测试] 开始")` | 字符串没包 `自定义字符串(...)` | `记入查看器(自定义字符串("[测试] 开始"))` |
| `播放效果(双方, …)` | 玩家槽塞了队伍筛选词 | `播放效果(所有玩家(所有队伍), …)` |
| `i = 1;` | 变量赋值没带域（对应 `67738`） | `事件玩家.i = 1;` 或 `全局.i = 1;` |
| `设置受到伤害(事件玩家, 50%)` | `%` 在工坊里是**取余**，不是百分号（`51152` / `51161`） | 百分比参数写纯数字：`50` 就是 50% |

`ws.py check` 拦得住前两条（`E-51`）、`50%`、`i = 1` 这几种；`播放效果` 的玩家槽也拦。

**（4）等号右边写了动作（`51159` / `67739`）**

```
✗ 事件玩家.hudId = 创建HUD文本(事件玩家, …);
✓ 创建HUD文本(事件玩家, …);
  事件玩家.hudId = 上一个文本ID;
```

**（5）引号与换行（`52840` / `52841` / `51166`）**

字符串必须写在一行内、引号成对、注释里不能留未闭合的引号。
这三条现在**一条都拦不住**，是缺口清单里的 1 号（实现成本低、语料误报 0）。

另外两条容易误会：
- `51153` 关系运算子：条件里写成了赋值 `=`。
- `65581` 子程序规则可能没有条件：`子程序` 事件对应的规则不能带 `条件` 块，判断要挪进子程序体里的 `If`。

## 2. 类型（16 条）

类型层不是"类型标注错了"这么简单，这 16 条覆盖四种完全不同的东西：

1. **值的种类放错位置**：`50044` 字符串不能存变量、`70076` 局部值只能进视觉/HUD、`51164`/`67646` 槽位类型不匹配、`70586`/`70589`/`73023`/`73025`（设置值的类别/名称/选项必须是 `自定义字符串`）。
2. **作用域/上下文不对**：`50040` 持续-全局里用 `事件玩家`、`50041` 攻击者/被攻击者、`52256` 治疗者/被治疗者。
3. **数组遍历的隐含变量**：`50042` 当前数组元素、`70077` 当前数组索引，出了 For 就不能用。
4. **语义约束**：`50043` 叠加层数、`50049` 受限制的值、`50055` 非法的值、`65498` Chase 与 For 抢同一个变量。

| 写法 | 能不能过 |

**（2）`错误：第%2$s行的“%1$s”之后应有一个地图名称`（`54290`）**

原因：`釜山寺院` 这种**带子区域**的名字，游戏先认出「釜山」，把后面的字当成下一段。
改法：只写主图 `釜山`；或用编辑器里的实际写法（在编辑器选一次，导出看它怎么写）。

**（3）`错误：第%2$s行的“%1$s”之后应有一个游戏模式设置`（`65689`）**

原因：**模式名写错**。编辑器显示名和 `.ow` 里的块名不同：

| 编辑器显示 | `.ow` 里写 |
|---|---|
| 攻击/护送 | `攻击护送`（没有斜杠） |
| 角斗领域（训练靶场） | `角斗领域 训练靶场` |
| 占领要点（6V6） | `占领要点 6v6`（小写 v） |

**（4）`错误：第%2$s行的“%1$s”之后应有一个队伍设置`（`65719`）**

**看到这句先去看 `英雄` 块的结构**，不是去看队伍设置——文案会把人带偏。
`.ow` 里 `英雄` 块必须分层：`英雄 > 综合（或 队伍1 / 队伍2）> 英雄名 > 键`，
`启用英雄 { … }` 也必须写在 `综合` / `队伍1` / `队伍2` **里面**：

```
英雄
{
	综合
	{
		路霸 { 受到伤害量: 200% }

		启用英雄 { 路霸 }     ← 在这里
	}
}
```

写成 `英雄 { 路霸 { … } 启用英雄 { … } }`（少了 综合 那一层）→ 导入就报这句，
而且报错指向「受到伤害量: 200%」那一行，看着像值的问题，其实是层级问题。
`ws.py check` 会直接点名：「「启用英雄」要写在 英雄 > 综合 里面，现在挂在「英雄」下」（`E-45`）。

**（5）`错误：无效的队伍设置`（`65729`）+ `大厅设置无效。你必须调整或撤销改动。`（`68106`）**

同一个原因，两种表现（导入时报前者，界面退不出当前页时弹后者）。四种情况：

| 情况 | 怎么确认 | 怎么改 |
|---|---|---|
| 单队 `玩家上限` 超过 12 | `ws.py check` 会说「超出范围（0~12）」 | 改成 ≤ 12 |
| `队伍1 + 队伍2` 合计超过 12 | check 会说「合计 N 人，超过大厅总共 12 个栏位」 | 6+6、8+4、12+0 |
| **只写了一队又超过 7**，另一队仍是大厅默认 5 人 | check 会说「只写了 玩家上限 队伍1 = 8…合计 13 超过 12」 | 另一队显式写 `0` |
| 团队模式写了 `自由混战人数上限`，或死斗把它写成 0 | check 会按模式点名 | 团队模式写 0；死斗写 1 以上 |

**（6）`尚未选择地图。你必须调整或撤销设置改动。`（`25575` / `50028`，B 层）**

两种原因，报错原文相同：

| 原因 | 怎么判断 | 改法 |

**（7）设置键「过期」那句话不是游戏原文**

见附一。`设置「X」不在当前版本的数据表里` 是 `ws.py check` 自己造的话，

| 74809 | `错误：过多的地图工坊设置选项。` | 每个英雄每项都写了设置 | 只写需要改的项，其余用默认 | 不能 / 配额 | 无 |
| 76429（B 层） | `已用扩展点数不能超过可用扩展点数` | 开的扩展太多，或大厅栏位少导致可用点数不足 | 减扩展；可用点数 = 4 × 空栏位数（推断） | 不能 / 配额 | 无 |
| 76448 | `错误：已用扩展点数不能超过可用扩展点数` | 开的扩展太多，或大厅栏位写小导致可用点数变少 | 减扩展，或把大厅空栏位调大（可用点数 = 4 × 空栏位，推断值） | 不能 / 配额 | 无 |
| 76840 | `错误：已用地图工坊扩展点数过多；请移除一项或多项扩展。` | 开的扩展太多，或大厅栏位写小导致可用点数变少 | 减扩展，或把大厅空栏位调大（可用点数 = 4 × 空栏位，推断值） | 不能 / 配额 | 无 |
### 深挖：上限类，数字从哪来

**（1）单条规则 98 KB（`62494`）**

原文是 `每条规则长度不得超过%1$sKB`，`%1$s` 是填进去的上限。实测值 98 → `ws.py check` 按 100352 字节判，超了直接 error。

**（2）元素数 32768：这句在 CASC 表里找不到**

`0x07C` 里与元素上限有关的只有面板标签 `总计元素数量`（`62491`），**没有一句「超过上限 32768」**。
这个 32768 来自编辑器诊断面板的上限与实测，不是报错原文，见附一。
`ws.py count` 给的是估算区间，接近上限时以游戏内「显示诊断结果 → 总计元素数量」为准。估算系统性低估（系数约 2.12），所以估算值已超 32768 时一定是真超。

**（3）扩展点数（`76429` / `76448` / `76840`）**

- `已用扩展点数不能超过可用扩展点数`（两条同义，带不带「错误：」前缀）。
- `已用地图工坊扩展点数过多；请移除一项或多项扩展。`
- 可用点数**不是固定 8**：`可用点数 = 4 × 空栏位数`（推断值，见 `docs/extensions.md` §三），栏位又被大厅的 `玩家上限` 与地图开关决定。
  所以静态算不出超没超，`ws.py check` 只报「已用多少 + 基础可用 8」，不当错误。

**（4）房间级与服务器级**

- `51443` 由于地图工坊脚本过多，服务器已关闭。→ 整局被关，不是你一个文件的事。
- `61873` 过多自定义字符串、`70585`/`74809` 过多的地图工坊设置（选项）：单文件也可能踩，但上限数值未验证。

按缺口该补哪类检查（A 层，部分+不能 共 79 条）：

| 名字 | 30 | 变量/子程序索引重复与越界、名称长度与非法字符、重名、扩展名 |
| 类型 | 16 | 事件上下文值、数组外用、字符串入变量、叠加、受限值 |
| 语法 | 14 | 引号/换行/注释、剪贴板段、规则缺事件、关系运算子 |
| 配额 | 8 | 自定义字符串数、设置项数、扩展点数、动作列表复杂度 |

### 9.2 前 5 条低成本草案（1 / 3 / 4 已实现，2 部分已实现，5 未做）

> **实现状态（v3.13.0 之后，PLAN v5 A2）**：草案 1（逐行奇数引号）、草案 4（规则缺事件块）已接成 **error**，
> 草案 3 收窄成「变量名 / 子程序名 > 32 字符」**warning**。三者在 9 份真实语料上 **零误报**，
> 各有一条专属反向用例（`odd-quote.ow` / `rule-no-event.ow` / `long-var-name.ow`），`check-all` 反向 52/52。
> **规则名长度那条撤回了**：真实模式的规则名常带 `## ` / `———` 这类排版前缀、动辄 40 字符，
> 一开就是 20+ 条误报（D-006 门槛 3 条）。

**草案 1：引号闭合 / 字符串内裸换行（覆盖 `52840` `52841` `51166`）——已实现（error）**

- 输入：`.ow` 全文；按**物理行**数双引号（跳过 `//` 注释、处理 `\"` 转义）。
- 输出：奇数引号 → error「这一行双引号是奇数（N 个），字符串没闭合 —— 游戏会报『文本字符串中出现了换行』」。
- 为什么按物理行：字符串不能跨行，所以单行奇数就是没闭合；整篇奇偶会因为注释里的引号误判。
- 误报：实测 138 个样本 19,263 行 + 9 份真实语料，奇数引号 **0 行**。

**草案 2：变量/子程序 重复索引 + 重名 + 子程序重复定义（覆盖 `60280` `65533` `60193` `60203` `60285` `60290` `65245` `65607`）**

- 输入：`变量` 块（按 `全局:` / `玩家:` 分域）、`子程序` 块。
- 输出：同一域内索引重复 → error；同一域内重名 → error；`子程序` 块索引重复 → error；两条规则声明同一个子程序 → error。
- 误报风险：**低，但有一个坑必须避开**：不能查「索引必须连续」。实测 92 份变量块 / 104 个域里 **7 个域**是不连续的（`golden2.ow` 全局缺 2、9、23），这些文件能正常导入 —— 查连续性就是给自己制造 7 条误报。
- 实测底数：104 个域，重名 0、重复索引 0。

**草案 3：名称长度上限（覆盖 `60206` `60207` `60282` `60289` `65243` `65534`，warning）——已实现（收窄到变量/子程序名）**

- 输入：变量名、子程序名的字符数（**规则名不算**，见下）。
- 输出：> 32 字符 → warning「名字超过 32 字符；游戏会报『包含过长的名称』（真实上限未验证）」。
- 误报：实测 138 个样本里最长名字 17 字符（`golden2.ow` 的 `PayloadPercentage`）、最长子程序名 10；
  9 份真实语料 0 命中。**规则名一开就 20+ 条**（`## 决斗资格获取`、`———符文子程序` 这类排版名），已撤回。
- 为什么只能 warning：上限真值没测出来（`60206` 只说明"过长"存在，不给数字）。

**草案 4：规则必须带 `事件` 块（覆盖 `51154` `51160`）——已实现（error）**

- 输入：每个 `规则("…") { … }` 块（按物理行，`禁用 规则` 也算）。
- 输出：块内找不到 `事件` 段 → error「这条规则没有 事件 块，游戏会报『之后的规则没有以事件结尾』」。
- 误报：实测 219 个规则块缺 0，9 份真实语料 0 命中。子程序也有 `事件` 块（`子程序; X;`），不影响。

**草案 5：事件上下文值（覆盖 `50041` `52256`，先做 warning）**

- 输入：规则的事件名 + 该规则里出现的 `攻击者` / `被攻击者` / `治疗者` / `被治疗者`。
- 输出：`攻击者`/`被攻击者` 出现在非战斗事件 → warning；`治疗者`/`被治疗者` 同理。
- 误报风险：**中**。138 个样本里这四个值出现 **0 次**，语料标定不了；事件白名单只能从 `data/events.tsv` 加报错原文点到的两个事件（玩家参与消灭、玩家受到治疗）反推，先 warning 跑一轮再决定要不要升 error。

### 9.3 明确不做的（做了就是误报）

| 想法 | 为什么不做 |
|---|---|
| 索引必须连续 | 实测 7 个域不连续仍能导入（见草案 2），这是假规则 |
| 已用扩展点数 > 可用点数 | 可用点数由大厅栏位与地图开关决定，静态算不出（`docs/extensions.md` §三 已定「不做」） |
| 元素数精确值 | 只有估算（系数 2.12），临界带只能 warning |
| 剪贴板段完整性（`51130`/`51158`） | `.ow` 文件里没有剪贴板段标记，这两句只在「从剪贴板导入」那条路出现；文件截断大多已被括号配对拦住 |
| 运行时类（`24164`/`51027`/`50052`） | 导入前不存在判据 |
