# 报错对照手册

游戏报错只给一句话，不给原因、常常连行号都不对。下面是**实测确认过的对应关系**，按“报错原文 → 真正原因 → 怎么改”排列。

> 行号陷阱：游戏报的行号经常指向**上一行**或**下一个符号**，不是出错的那一处。先用 `ws.py check` 定位，再看游戏报错。

---

## 一、地图相关

### `无效的地图设置`

| 可能原因 | 怎么确认 | 怎么改 |
|---|---|---|
| 这张图**不在该模式的地图池**里 | `ws.py check` 会直接说「不在「占领要点」的地图池里」 | 换成池子里的图；池子见 `data/map-pools.tsv` |
| 时段**编号写错了** | 该图没有这个时段，或编号属于别的时段 | 删掉编号，只写地图名（一定可用） |
| 用了**坏图** | 埃斯佩兰萨、斗兽场写任何编号都失败（游戏数据缺陷） | 这两张只写名字 |
| 子图名字写法不对 | 见下一条 | 见下一条 |
| **写了地图内部的子区域名** | 例：`釜山寺院`、`釜山城区`、`釜山体育场` —— 釜山是**一张图含三个子区域**，编辑器里只有「釜山」一个入口 | 写「釜山」即可（`data/map-not-in-editor.tsv` 有清单，`ws.py check` 会点名） |

### `第N行的"釜山"之后应有一个地图名称`

原因：`釜山寺院` 这种**带子区域**的名字，游戏先认出「釜山」，把后面的字当成下一段。

| 改法 | 说明 |
|---|---|
| 只写主图 `釜山` | 最稳 |
| 或用编辑器里的实际写法 | 在编辑器选一次，导出看它怎么写的 |

### `第N行的"..."之后应有一个游戏模式设置`

原因：**模式名写错**。编辑器显示名和 `.ow` 里的块名不同：

| 编辑器显示 | `.ow` 里写 |
|---|---|
| 攻击/护送 | `攻击护送`（没有斜杠） |
| 角斗领域（训练靶场） | `角斗领域 训练靶场` |
| 占领要点（6V6） | `占领要点 6v6`（小写 v） |

### `尚未选择地图，你必须调整或撤销设置改动`

两种原因，报错原文相同：

| 原因 | 怎么判断 | 改法 |
|---|---|---|
| 在「设置 / 地图」页点了**关闭所有** | 你刚在编辑器里关过图 | 别全关；要换图就逐张开关 |
| **地图名在该模式下选不到**（写成了整图/场景的另一种，或该模式根本没这张图） | 报错是导入文件时出现的 | 按 `data/map-pools.tsv` 里该模式记的写法逐字改（2026-10-23 实机：突击模式写「伊利奥斯废墟」、死斗写「伊利奥斯」、勇夺锦旗写「釜山」都被拒） |

## 二、设置与自定义设置

### `每一个地图工坊设置只能被引用一次，且必须有唯一一个名称（忽略空格和大小写）`

原因：`地图工坊设置整数/开关/字符串` 的**自定义名重复**了。

改法：每个自定义设置用独立名字。批量生成时特别容易踩——同名设置写 10 次就报这个。

### `设置「X」不在当前版本的数据表里`

原因：键名过期或拼错（官方改过名）。

改法：`ws.py settings <模式>` 查当前可用键；或 `ws.py explain "报错原文"` 反查。

### `无效的选项`

原因：下拉参数填了不在选项里的值。

改法：`ws.py doc <动作名>` 看该参数的合法选项。

### `局部值只能用于视觉效果或HUD动作`

**先查一件事：有没有把「本地玩家」存进全局变量。**

游戏这句报错只针对**存储**这一件事，不是「本地玩家 一概不能用在动作里」：

| 写法 | 能不能过 |
|---|---|
| `创建HUD文本(本地玩家, …)`、`大字体信息` 等 HUD / 特效动作 | 能 |
| `If(本地玩家.某变量 …)`、`等待直到(…本地玩家…)`、`生成机器人(本地玩家…)` | 能（真实语料里大量这么写） |
| `设置全局变量(x, 生命值(本地玩家))` | **不能** |
| `全局.x = 生命值(本地玩家);`（裸赋值，同义） | **不能** |

改法：
- 存玩家自己的数据 → 用**玩家变量**：`玩家.x = …`，读的时候 `事件玩家.x`
- 规则需要「这个人」→ 把事件换成 `持续 - 每名玩家; 双方; 全部;`，之后一律用 `事件玩家`

`ws.py check` 会把两种写法都点名，并给出这句话当依据。

### `第N行的"…"之后应有一个队伍设置`

**看到这句，先去看 `英雄` 块的结构**，不是去看队伍设置——这句文案会把人带偏。

`.ow` 里 `英雄` 块必须分层：`英雄 > 综合（或 队伍1 / 队伍2）> 英雄名 > 键`，
`启用英雄 { … }` 也必须写在 `综合` / `队伍1` / `队伍2` **里面**：

```
英雄
{
	综合
	{
		路霸 { 受到伤害量: 200% }

		启用英雄 { 路霸 }     ← 在这里
	}
}
```

写成 `英雄 { 路霸 { … } 启用英雄 { … } }`（少了 综合 那一层）→ 导入就报这句，
而且报错会指向「受到伤害量: 200%」那一行，看着像值的问题，其实是层级问题。

`ws.py check` 会对这种写法直接点名：「「启用英雄」要写在 英雄 > 综合 里面，现在挂在「英雄」下」。

### `错误：无效的队伍设置`（界面里是「大厅设置无效。你必须调整或撤销改动。」）

这是**大厅栏位**的合法性检查，跟语法无关。四种情况会踩到：

| 情况 | 怎么确认 | 怎么改 |
|---|---|---|
| 单队 `玩家上限` 超过 12 | `ws.py check` 会说「超出范围（0~12）」 | 改成 ≤ 12 |
| `队伍1 + 队伍2` 合计超过 12 | check 会说「合计 N 人，超过大厅总共 12 个栏位」 | 6+6、8+4、12+0（单人 12+0） |
| **只写了一队又超过 7**，另一队仍是大厅默认 5 人 | check 会说「只写了 玩家上限 队伍1 = 8…合计 13 超过 12」 | 另一队显式写 `0`（或写小一点），单队想写 8 以上就必须把另一队写出来 |
| 团队模式写了 `自由混战人数上限`，或死斗模式把它写成 0 | check 会按模式点名 | 团队模式写 0；死斗写 1 以上 |

**注意**：这个错游戏不会指到具体哪一行（只给一句「无效的队伍设置」），所以先跑一次 `ws.py check` 比在游戏里猜快得多。
界面上则是退不出当前页、弹「大厅设置无效」——同一个原因，两种表现。

## 三、语法与书写

### `第N行的"50"之后应有';'`（参数写少了）

签名里尾部参数写着「可以省略」，**游戏不一定认**。

```
✗ 创建效果(…, 球体, 颜色(白色), 矢量(0,3,0), 5)          ← 5 个参数
✓ 创建效果(…, 球体, 颜色(白色), 矢量(0,3,0), 5, 可见)     ← 6 个
```

真实语料里 `创建效果` 出现几十次，**最小也是 6 个参数**。`ws.py check` 现在会提示：
`创建效果 这里写了 5 个参数，语料里最少写 6 个`。
通用做法：**语料里怎么写就怎么写，不要按签名省参数。**

### `第N行的"上"之后应有';'`（值函数名写错 / 不存在）

```
✗ 全局.g4 = 上一个效果ID;      ← 没有这个函数
✓ 全局.g4 = 上一个文本ID;      ← 存在
✓ 全局.g4 = 数量(最后创建的实体());   ← 效果要用「最后创建的实体」
```

数据表里带「上一个」的无参值函数只有：`上一个文本ID`、`上一个伤害调整ID`、`上一个治疗调整ID`、
`上一个助攻ID`、`上一个持续伤害效果ID`、`上一个持续治疗效果ID`。
写错名字游戏只会说「"上"之后应有';'」，指不到根因。`ws.py check` 现在直接报「值函数「X」不存在」并列出相近的名字。

### `第N行的"玩家数量("之后应有一个值`（同类：`"生成机器人("之后应有一个值`）

两类「参数写法不认」的同一个症状，游戏只会说「之后应有一个值」，指不到根因。

| 写法 | 真正原因 | 怎么改 |
|---|---|---|
| `玩家数量(全部)` | `全部` / `双方` 是**事件块的选择器词**，不是队伍值。队伍参数只认 `所有队伍` / `队伍1` / `队伍2`，而且 `所有玩家` 收 `所有队伍`，`玩家数量` / `生成机器人` 只收 `队伍1` / `队伍2` | 死斗里数是 `数量(所有玩家(所有队伍))`；按队取用 `队伍1` / `队伍2` |
| `生成机器人(死神, 队伍1, …)` | 英雄参数必须包 `英雄(…)` | `生成机器人(英雄(死神), 队伍1, -1, 空, 空)` |

`ws.py check` 两条都拦：`第 N 个参数是队伍，只能写 …` / `第 N 个参数是英雄，要写成 英雄(…)`。
死斗里塞机器人还有一层坑：`队伍1` / `队伍2` 没有栏位（栏位数 0），必须写 `所有队伍`——见 [pitfalls-runtime.md](./pitfalls-runtime.md)。

### `"记入查看器("之后应有一个值`

原因：字符串没包 `自定义字符串(...)`。

```
✗ 记入查看器("[测试] 开始")
✓ 记入查看器(自定义字符串("[测试] 开始"))
```

例外：单独一行写 `"注释"` 是合法的。

### `"="之后应有一个值`

等号右边写了个**动作**。动作不返回值，只有「值函数」能放右边。

```
✗ 事件玩家.hudId = 创建HUD文本(事件玩家, …);
✓ 创建HUD文本(事件玩家, …);
  事件玩家.hudId = 上一个文本ID;
```

`上一个文本ID` / `上一个效果ID` 这类值函数必须在**对应的创建动作之后**立刻取。

### HUD 建了但屏幕上没有

不是报错，是「重新赋值」选错：`字符串` 只改已有文本，不会创建。首次要 `可见和字符串`。
详见 [pitfalls-runtime.md](./pitfalls-runtime.md)。

### `播放效果(` 之后应有一个值 / 队伍筛选词塞进动作

原因：动作的「可见玩家」这类**玩家槽**填了 `双方`、`所有队伍`、`队伍1` 这类**队伍筛选词**——
它们只用得在事件行（`事件 { …; 双方; 全部; }`）。

```
✗ 播放效果(双方, 有益爆炸, 颜色(黄色), 事件玩家, 1);
✓ 播放效果(所有玩家(所有队伍), 有益爆炸, 颜色(黄色), 事件玩家, 1);
```

### `第44行的"8,"之后应有一个值`

原因：队伍类参数写了「双方」。**「双方」只能用在事件筛选**，动作里要用 `所有队伍` / `队伍1` / `队伍2`。

行号指向的是半径参数，不是真正出错的地方。

### `"1);" 之后应有一个值`

原因：变量赋值**没带域**。

```
✗ i = 1;
✓ 事件玩家.i = 1;      或      全局.i = 1;
```

### `第N行的"50%"之后应有一个值`

原因：**把百分比写成了 `%` 后缀**。工坊里的 `%` 不是百分号，是**取余运算符**（语料实证：`总计消耗时间 * 60 % 360`），
所以 `50%` 会被读成「50 取余 缺右操作数」。

```
✗ 设置受到伤害(事件玩家, 50%);
✓ 设置受到伤害(事件玩家, 50);
```

百分比参数在 `.ow` 里一律是纯数字：`50` 就是 50%。`ws.py check` 会直接点名这一行。

### `End;` 相关报错

原因：`If` / `While` / `For` 没有配对的 `End;`。

注意：真实导出的文件本身就常缺 `End;` 却能导入，所以校验器默认不查这条（`--strict` 才查）。真报错了再补。

## 四、容量限制

### `总计元素数量超过上限 32768`

`ws.py count 文件.ow` 看估算区间。接近上限时以游戏里「显示诊断结果 → 总计元素数量」为准。

### `单条规则超过 98 KB`

把一条巨规则拆成几条。

## 五、怎么快速定位

```bash
python tools/ws.py check 我的模式.ow          # 必改 / 提示 分级
python tools/ws.py check 我的模式.ow --strict  # 更严（会多出 End; 配对、语义检查）
python tools/ws.py explain "无效的地图设置"    # 反查报错文案
python tools/ws.py report 我的模式.ow         # 生成可上报的脱敏片段
```

游戏报错原文可以直接贴给 AI，让它先跑 `check`，再对照本手册。
