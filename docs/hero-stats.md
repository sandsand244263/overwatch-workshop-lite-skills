## 数据在哪（重新提取时用）

```
0x075 STUHero
  └ m_heroLoadout → 0x09E STULoadout
      └ 6 个引用槽位
          └ 0x130 STU_A0E5F3ED
              ├ m_name       中文名
              ├ m_1B39F279   当前值
              ├ m_3E5360A1   基础值
              ├ m_values[]   数值曲线
              └ m_09739F24   子节点
```

槽位含义：

| 槽位 | 含义 |
|---|---|
| `m_6994A2CF` | 生命值 / 护甲 / 护盾 |
| `m_13EF906E` | 冷却时间 |
| `m_5D621D4D` | 弹匣 |
| `m_8D4E0678` | 装填 |

## 缺什么，为什么

**技能伤害（`岚` 75、`裂地重拳` 60 这类）没拿到。**

原因：技能数值在实体定义（`0x003`）的 `STUStatescriptComponent` 里，是一组 **「`0x01C` 变量 ID → 数值」** 对（半藏 257 组）。

`0x01C` **不是资产**——直接 `OpenFile` 会 `FileNotFoundException`（已实测确认）。所以必须先找到**变量注册表**，把 ID 映射成字段名（"伤害量"、"最大持续时间"、"弹道速度"）。

工作量估计：**0.5–1 天**，验收判据现成（`out/raw/entity_components.txt` 里 257 组 ID/值，对上岚 75/5/110 即可）。

## 覆盖缺口

- 英雄属性缺 5 个：D.Mon、堡垒、朱诺、血律、金驭（新英雄结构不同，槽位未对上）
- 技能数值只覆盖 26 个英雄，且以冷却/弹匣为主

## 用途

模式设计时判断量级：这英雄多少血、技能多久一次、弹匣几发。**别用来算精确伤害**——伤害表还没有。
