# 探针模板与判读规范（probe-spec）

> 阶段 0-4：把「跑探针 → 抄读数 → 人工比对」改成「生成模板 → 跑一次 → 一条命令出差异表」。
> 工具：`tools/gen_probe.py`（`ws.py probe-template`）生成，`tools/logread.py`（`ws.py readlog --expect-file`）判读。
> 本文只讲约定；运行时行为本身仍然只写在 [pitfalls-runtime.md](./pitfalls-runtime.md)。

## 一条命令的闭环

```bash
# 1) 生成探针骨架 + 配套期望表
python tools/ws.py probe-template --cells 8 --out 探针.ow
#    -> 探针.ow（8 格，每秒打点，12 秒自停）
#    -> 探针.expect.tsv（期望/容差已按结构和秒数算好，依据列留「未验证」）

# 2) 校验（必须 0 error 再进游戏）
python tools/ws.py check 探针.ow

# 3) 进游戏跑一次 → 打开查看器 → 点底部「复制记录到剪贴板」→ 粘进 records.txt
#    （游戏自己落盘的那个 Log-*.txt 时有时无，不能当依赖）

# 4) 判读：出「预期 | 实际 | 结论」差异表
python tools/ws.py readlog --file records.txt --expect-file 探针.expect.tsv
```

记录格式统一是 `[时:分:秒] [标签] 内容`（UTF-8、LF）。查看器复制出来的内容与落盘文件**同格式**，
所以两条路都能喂给 `readlog`：`--file` 指定文件，不给就去找目录里最新的 `Log-*.txt`。

## 为什么一格一计数器

一条规则只回答一个问题，计数器就是那个问题的答案。

| 反例 | 会发生什么 |
|---|---|
| 多个结构共用一个计数器 | 读数上去了，但**分不清是谁推上去的**；只能重跑、加打印、再猜 |
| 一条规则里塞两个「测试」 | 条件互相干扰（一个 `While` 卡住，另一个永远轮不到） |
| 用 HUD 显示计数 | `大字体信息` 有动效、跟不上每秒一条，界面显示的是旧值（实测，见 pitfalls-runtime） |
| 用事件规则做轮询 | 事件规则同时只有一份执行，忙的时候事件被丢弃（E-50） |

所以模板固定成：**一格 = 一条 `持续` 规则 + 一个 `cN` 计数器 + 每秒一条 `记入查看器`**。
`cN` 与规则名、日志标签三者同号，日志里一眼能对上格子。

## 模板硬约定（生成器会自查，不满足就不写文件）

1. **一格一计数器**：第 N 格的计数器固定叫 `cN`，全文件只有一处 `全局.cN = 全局.cN + 1`。
2. **单文件最多 20 格**：再多就拆文件；一个文件里规则互相抢执行窗口，读数不可信。
3. **必须带对照组**：对照组是「结构完全相同、只有条件不可能成立」的格子。
   - 对照组必须与它的配对测试格同时在场，否则报错（`If假` 少了 `If真` 就没有意义）。
   - 对照组有两种「不该触发」的表现，对应期望表的两种写法：
     | 对照结构 | 现象 | 期望列写法 |
     |---|---|---|
     | `If假` / `While假` / `For循环0` / `每名玩家If假` | 规则在跑、每轮都打点，但值恒为 0 | `0` |
     | `条件块假` | 整条规则不执行，日志里连键都没有 | `未出现` |
4. **每秒打点一次，格式固定** `[cN] cN=<值>`，只走 `记入查看器`；不用 `大字体信息`/`小字体信息`。
5. **每个 `While` 都有退出条件**：模板一律写 `While(全局.t < 秒数)`，不写 `While(真)`。
   验证类探针的读数只需要一个固定窗口，写死时限比「跑完人肉叫停」可靠。
   万一必须用 `While(真)`，生成器要求它后面 30 行内有 `中断`，否则拒绝生成（死循环会卡住整场比赛）。
6. **持续类规则的开头先等开赛**：`等待直到(正在设置 == 假, 60);` + `等待(6, 无视条件);`
   —— `持续` 规则在加载和开局倒计时期间就在跑，不挡会白跑十几秒（实测，见 pitfalls-runtime）。
7. **屏幕隐蔽写在「每名玩家」规则里，且在等待之前**：
   `隐藏英雄HUD(事件玩家)` / `隐藏游戏模式HUD(事件玩家)` / `开始镜头(事件玩家, …)`。
   全局规则里对这些动作用 `本地玩家` 实测无效（E 编号见 pitfalls-runtime）。
8. **一个时钟管所有格子**：单独一条 `持续 - 全局` 规则每秒 `全局.t + 1`，
   所有格子的循环条件都读 `全局.t`，这样 8 个格子的窗口是同一个，读数可直接横向比较。

## 内置结构表

`gen_probe.py` 的 `STRUCTURES` 里现在有 12 种结构（5 对「测试 + 对照」+ 2 个单格基线）：

| 结构 | 事件 | 循环体内 | 每轮预期 | 配对对照 |
|---|---|---|---|---|
| `无条件` | 全局 | 直接 +1 | 1 | —（基线） |
| `等待0` | 全局 | `等待(0, 无视条件)` 后 +1 | 1 | —（验证零等待不卡循环） |
| `If真` | 全局 | `If(1 == 1)` 包住 +1 | 1 | `If假` |
| `If假` | 全局 | `If(1 == 2)` 包住 +1 | 0 | （对照） |
| `条件块真` | 全局 | 条件块 `1 == 1` | 1 | `条件块假` |
| `条件块假` | 全局 | 条件块 `1 == 2` | 0（**键不出现**） | （对照） |
| `While上限` | 全局 | 内层 `While(aux < 3)` | 3 | `While假` |
| `While假` | 全局 | 内层 `While(1 == 2)` | 0 | （对照） |
| `For循环` | 全局 | `For 全局变量(i, 1, 4, 1)`（不含终止值 = 3 次） | 3 | `For循环0` |
| `For循环0` | 全局 | `For 全局变量(i, 1, 1, 1)`（空区间） | 0 | （对照） |
| `每名玩家` | 每名玩家 | 直接 +1（每人一个实例） | 1 × 人数 | `每名玩家If假` |
| `每名玩家If假` | 每名玩家 | `If(1 == 2)` 包住 +1 | 0 | （对照） |

`--cells N` 按「成对优先」拼：N=2 → `If真/If假`；N=8 → 四对（If、条件块、While、每名玩家）；
N=12 → 全部结构。要别的组合用 `--structures 无条件,If真,If假,…` 显式指定。

## expect.tsv 格式

制表符分隔，第一行表头，`#` 开头是注释行：

```
格号	结构说明	期望	容差	依据	备注
c1	If真	12	±2	未验证	循环体内 If(恒真)
c2	If假	0		未验证	对照组（配对 If真）
c4	条件块假	未出现		未验证	对照组：整条规则不执行
c7	每名玩家	>=12		未验证	两人在场时翻倍
```

| 列 | 说明 |
|---|---|
| 格号 | **计数器变量名**（`c1`…），不是「第几格」。判读时按这个名字在日志里找 `键=值` |
| 结构说明 | 人看的；建议写结构名 + 一句话 |
| 期望 | 目标值。写法见下；空着或写 `*` = 不判 |
| 容差 | 可空。写法见下；空 = 期望按精确值判定 |
| 依据 | 这条期望从哪来（E 编号 / 文档 / 未验证）。生成器留「未验证」占位 |
| 备注 | 补充说明；判读时只在没通过的格子下面打印 |

### 期望列的写法

| 写法 | 含义 |
|---|---|
| `12` / `12.5` | 精确相等（有 `±T` 容差时变成「中心值」） |
| `12±2` | 自带容差，等价于 期望 12 + 容差 `±2` |
| `>=10` `>10` `<=10` `<10` `==10`（也认 `≥` `≤`） | 不等式 |
| `10..20` | 闭区间 |
| `未出现`（也认 `缺席` / `none` / `absent`） | 这个键**不该**出现在日志里；出现了就是「不符」 |
| 空 / `*` | 不判期望，只看容差 |

### 容差列的三种写法

| 写法 | 含义 | 例 |
|---|---|---|
| `±2` | 以期望为中心、上下各 2 | 期望 12 → 实际 10~14 都算通过 |
| `>=10`（`<=` `>` `<` 同理） | 对**实际值**的单边要求 | 期望写 `20`、容差 `>=10` → 实际 20 满足 |
| `540..560` | 实际值落在闭区间 | 期望列可留空 |

- 容差写 `±T` 时**期望必须是数字**（中心值），否则报错。
- 容差写 `>=` / `..` 时，期望只做展示，判定完全由容差决定。
- 单独写一个数字（如容差列写 `2`）是错的——会报错，不猜你的意思。

### 判错不静默

`12左右`、`几个`、`1~12`、区间写反（`20..1`）这类看不懂的写法，会**列出文件行号并让命令以退出码 2 结束**，
不会当成 0 或者「跳过这一行」。表头缺「期望」列、格号重复、列数不够同样直接报错。

## 结论四档与退出码

| 结论 | 什么情况 | 汇总里计入 |
|---|---|---|
| 通过 | 期望与容差都满足；或期望写 `未出现` 且键确实没出现 | 通过 |
| 不符 | 键出现了，但值不符合期望（无容差时的精确比对，或 `>=`/`..`/`未出现` 被违反） | 不符 |
| 未出现 | 日志里找不到这个键（规则没跑、条件没成立、或探针没生效） | 未出现 |
| 超容差 | 值出来了、期望也对得上，只是超出容差范围 | 单独一行列出（不塞进「不符」里，因为「方向对了量级不对」和「根本没跑起来」是两回事） |

末行固定是汇总：`N 格：通过 x / 不符 y / 未出现 z`。

**退出码：0 仅当全部通过**；有任一格不是通过 → 1；表本身有问题（读不到、写法看不懂、表头错）→ 2。

## 实测样例（真实日志）

拿 `Log-2026-10-24-10-21-35.txt`（8 格矩阵探针的历史读数）当输入，两种表各跑一次：

```
期望表：logs-2026-10-24.expect.tsv（9 格）
  格号     结构说明                   预期       实际       结论
  g1       历史探针 计数器1           1          1          通过
  g3       历史探针 计数器3           275        275        通过
  g5       历史探针 计数器5           >=19       20         通过
  g8       历史探针 计数器8           540..560   550        通过
  zz9      日志里不该有的键           未出现     （没出现） 通过
9 格：通过 9 / 不符 0 / 未出现 0            <- 退出码 0
```

故意写错的表（`g1` 期望 2、`g2` 期望 5±2、`g5` 容差 `>=1000`、`c1` 是这份日志里没有的键）：

```
  g1       历史探针 计数器1           2          1          不符
  g2       历史探针 计数器2           5          0          超容差
  g5       历史探针 计数器5           20         20         超容差
  c1       本模板的格号（这份日志里…  12         （没出现） 未出现
6 格：通过 2 / 不符 1 / 未出现 1            <- 退出码 1
```

## 判读之后

- 全部通过：把结论写进 `docs/rules.tsv`（`ws.py verify --set … --level L3 --evidence E-xx`），
  并把期望表里的「依据」从「未验证」改成对应证据编号。
- 有「未出现」：先分清是**结构本身不该触发**（对照组的正常表现）还是**探针没生效**
  （隐蔽规则卡住、时钟没起来、导入的是旧文件）。差异表的「打点 0 次」就是这个信号。
- 有「超容差」：通常是窗口抖动（开局等待、加载差异），先放宽容差重跑一次；
  连续两次都偏同一个方向，才是真结论。
- 有「不符」：先看「打点 N 次」——N 明显少于其他格子说明这条规则的循环被别的规则抢了执行时间，
  不是逻辑错。

## 未验证的部分（写清楚，别当成结论）

- 模板的**运行时读数**没有实机验证：本轮只做到「生成的文件 `ws.py check` 0 error」。
  结构表里的「每轮预期」是按文档与已有实测（E 编号见 pitfalls-runtime）推的，不是新跑出来的。
- `每名玩家` 的期望写 `>=秒数`：两人在场时读数应翻倍，但**机器人中途加入会补一次实例**，
  具体倍数要按当场人数算，模板故意不给精确值。
- `条件块真` 这一格的上升沿时机（加载期 vs 开赛后）没有单独测过；读数预计仍是约等于秒数，
  但如果明显偏小，说明上升沿被开局阶段吃掉了。
