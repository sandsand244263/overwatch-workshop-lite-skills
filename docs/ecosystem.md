# 生态：周边工具怎么配合

工坊这块的能力是分层的，本 skill 只管"写对"，其余交给下游工具。

## 一、分工表

| 工具 | 管什么 | 什么时候用 | 注意 |
|---|---|---|---|
| **本 skill（WorkshopLite）** | 写：语法、参数、枚举、设置项、格式校验 | 从想法到生成可导入代码 | 生成后必须跑 `tools/ws.py check` |
| **VS Code 插件**（xhanl/overwatch-workshop） | 补全、跳转、格式化、导入导出、**混淆** | 手工改代码、要 IDE 体验、发布前做混淆 | 见下面第二节 |
| **workshop.codes** | 在线编辑器、linter、代码分享、社区模式 | 想参考别人的实现、想让别人在线看/复制 | **只解析英文语法**，不能校验中文 `.ow` |
| **overpy** | 高级语言 ↔ 工坊代码（编译/反编译） | 想读懂一大坨被人混淆过的代码、想用 Python 风格写 | 反编译出来是 .opy，不是 `.ow` |
| **OWLib / DataTool** | 从游戏本体导数据（元素、枚举、字符串、设置项） | 游戏更新后同步数据 | 导出前必须关闭游戏与战网 |

## 二、VS Code 插件的混淆功能（5 项）

命令名 `ow.command.obfuscate`，运行前会让你填**原生代码的元素总数**（地图工坊 → 显示诊断结果 → 总计元素数量；上限 32768）。可勾选：

| 选项 | 做什么 | 副作用 |
|---|---|---|
| 混淆规则 | 填充虚假规则 | 占元素额度 |
| 混淆变量 | 变量/子程序名改成不可读文本，并填充假变量 | 自己后续维护会很痛苦 |
| 混淆字符 | 隐藏字符串内容 | **影响字符串比较**（比如比对玩家名）。用 `/* @SKIP_OBFUSCATE_STRING */` 和 `/* @SKIP_OBFUSCATE_STRING_END */` 包住要保留的部分 |
| 混淆索引 | 把二次复制的代码索引数值打乱 | 影响服务器负载 |
| 混淆本地索引 | 本地索引数值不可读 | 影响客户端帧率 |

### 混淆颗粒度对照（我们的脚本 vs 插件）

| 插件项 | 本脚本选项 | 状态 | 说明 |
|---|---|---|---|
| 混淆规则（填充虚假规则） | `fill` | ✓ | 查看器警告 1 条 + 篡改保护 5 条 + 1 元素空规则铺到 `--budget` 为止（默认 32000，规则数上限 11500） |
| 混淆变量（改名） | `vars` | ✓ | 声明和引用同步改，`攻击方.xxx` 这种前缀引用也认 |
| 混淆变量（填假变量） | `fakevars` | ✓ | 变量表/子程序表整表重建成 128 条，真名混在假名里 |
| 混淆字符 | `strings` | ✓ | 字符位移到私用区码位；`/* @SKIP_OBFUSCATE_STRING */` 之间不动 |
| 混淆索引 | `indexes` | ✓ | `[21]` → `[(21 * 9 / 9)]`，恒等写法（**不赌浮点**，issue #9） |
| 混淆本地索引 | `local-indexes` | ✓ | 只有客户端计算的那 15 个函数用小数抖动，`[3]` → `[3.27]` |
| 移除注释 | `comments` | ✓ | `//`、`/* */`、独占一行的 `"…"` |
| 移除规则名 | `rulenames` | ✓ | `规则("名字")` → `规则("")` |
| 删查看器条目 | `viewer` | ✓ | 记入查看器 / 启用查看器录制 / 禁用查看器录制 |

**还差的**：插件混淆时会把规则区空白全压掉再按 `{} ;` 重排，我们不动排版（改完没法读，也没实际保护价值）。
本地索引抖动方向也收紧了：插件是 ±0.4，我们只往正方向偏 0～0.4，免得游戏截断时变成 `n-1`。

### 混淆会顺手抹掉什么（核对插件源码 obfuscate.ts）

插件的「混淆」不只是改名，它在同一步里还会：

- **删注释**：`//…`、`/* … */`、独占一行的 `"…"` 字符串注释，统统删掉；
- **清空规则名**：`规则("名字")` → `规则("")`，规则名一律不留；
- **压掉空白**：规则区 `\s+` 全部去掉，再按 `{}`、`;` 重新换行（本脚本不压，避免动到排版习惯）。

本脚本对应 `comments` / `rulenames` / `viewer` 三个选项，`--obf all` 一次全做；
`fill` 对应插件的「按元素预算填充」，不给 `--budget` 时默认铺到 32000。
唯一没照搬的是空白压缩：不改排版，因为改完自己也读不了，且没有实际保护价值。
