| # | 要点 |

## 工坊执行机制（实测 2026-10-20）

- **`持续` 规则不会自己重入**。写成 `持续 - 全局` + `修改全局变量(n, 加, 1);`，10 秒后变量仍是 1——规则只执行了一次。
- **要持续做事必须显式循环**：`While(真); …动作…; 等待(0.1, 无视条件); End;`。同一条规则实测 3 秒 27 次、10 秒 90 次。
- 只加 `等待` 不算循环（`加1; 等待(0.1);` 实测仍是 1），必须 `While` 撑住。
- 推论：任何"每帧/定时"逻辑（HUD 刷新、计时器、状态检查、距离检测）都要按 `While(真)` 模板写；事件驱动的逻辑（伤害、击杀、按键）直接绑事件，不要靠轮询。

## HUD 的正确写法（实测 2026-10-20）

- **HUD 文本里的变量引用自动刷新**：`创建HUD文本(…, 自定义字符串("{0}", 全局.totalKills), …)` 建一次即可，数字会跟着变量变，**不要重复创建**
- 重复创建会堆叠：每条都会新增一行（实测 4 次击杀 → 4 行 HUD，虽然每行显示的都是最新值）
- 刷新槽的具体取值对"是否堆叠"没有影响
- `持续` 规则只执行一次，所以变量自增要靠**事件**（击杀、按键、受伤）或 `While(真)` + `等待`，不能指望规则自己跑第二遍
- 结论模板：HUD 建一次 + 变量由事件维护 = 活数字；不要用循环刷 HUD

## 设置块（实测 2026-10-20）

- `模式 > 综合` 实测能放 **7 个键**：`允许切换英雄` / `复生时间` / `急救包刷新` / `游戏模式开始` / `英雄限制` / `重装职责被动生命值加成` / `随机英雄复生`
- 早期认为"综合只认 4 个键"是**误判**：真正报错原因是 `允许切换英雄: 禁用` 用了导出器的老词，正确写法是 `关闭`
- **死斗模式没有 `玩家上限 队伍1/队伍2`**，团队模式才有——套模板时要按模式类型选
- 设置块只能整块照抄实测通过的样本（`tools/probes/_setup_template.txt`），不要手拼层级

## 等待 / 循环（实测 2026-10-20）

- `等待(时间, X)` 的 X **只能是 `无视条件` 或 `当为“假”时中止`**，填条件表达式会报「之后应有一个选项」
- 条件等待要自己写循环：`While(全局.条件 != 真); 等待(0.1, 无视条件); End;`
- `For 全局变量(i, 1, 5, 1)` 的终止值**不包含**：实际跑 1→4；控制变量必须先声明

## 数组 / 循环 / 事件（实测 2026-10-20 第二批）

- **数组追加**用 `修改全局变量(arr, 添加至数组, 值)`；`加` 是数值加法，会对数组求和（写成 `加` 结果是 6，不是三个元素）
- 变量初值是 `0`，追加后数组变成 `[0,1,2,3]`：长度比追加次数多 1，第 0 项是 0。要干净数组先 `设置全局变量(arr, 空)`
- `While(真)` 里 `If(条件); 中断; End;` **能跳出循环**（实测 c 停在 3）
- 自伤 `伤害(玩家, 玩家, 1000)` **会触发「玩家阵亡」事件**；玩家变量在阵亡后仍可读
- 开局有约 5 秒倒计时，期间规则已在运行；测时间相关行为要留 10 秒以上余量

## 数组下标从 0 开始（实测 2026-10-21）

```ow
设置全局变量(g, 数组(10, 20, 30));
// 实测结果（查看器）：
//   数组值的索引(全局.g, 10) = 0     ← 不是 1
//   数组值的索引(全局.g, 20) = 1
//   数组值的索引(全局.g, 30) = 2
//   数组值的索引(全局.g, 99) = -1    ← 找不到返回 -1（官方说明也这么写）
```

**坑在哪**：绝大多数语言直觉是"第一个元素是 1 号"，工坊里是 **0 号**。

- 取第一个元素：`全局.g[0]`
- 遍历 N 个元素：`For(i, 0, N - 1, 1)`，或 `For(i, 0, N, 1)` 靠"不含终止值"自然停在 N-1
- 判断"有没有找到"：结果 `== -1` 就是没找到，不要写 `== 0`

**注意别和 `For` 混淆**：`For(i,1,5,1)` 是从 1 数到 4（不含 5）；数组下标却是从 0 起。两者方向相反，写循环取值时最易错。

## 死斗的「获胜得分」就是目标分数（2026-10-21 实测）

设置块里写 `获胜得分: 1`，**杀一个就赢、比赛立刻结束**。

死斗这个键的范围是 **1–5000，默认 20**（数据实测），写 9999 会报「无效的游戏模式设置」。

测试模式和实测探针写 `获胜得分: 20`；`ws.py scaffold` 生成的骨架已改为 20。
校验器现在会检查 454 个设置键的取值范围。

## 真实模式的五种写法（2026-10-21，用 235 KB 实战模式验证）

拿一个真实上线的模式（8 个版本、最大 286 KB）跑校验器，一次报 **565 个 error**——**全部是误报**。真实代码里有五种教科书上没有的写法：

| 写法 | 例子 | 处理 |
|---|---|---|
| 块注释标记 | `/* @SKIP_OBFUSCATE_STRING */` | 逐行剥 `/* */`，未闭合的块注释连带剥 |
| 字符串注释行 | 单独一行 `"普通模式"` | 剥成空串后跳过，不当条件 |
| 跨行条件 | `(甲 \|\|` 换行 `乙)==真;` | 括号未闭合就并到起始行，后续行留空 |
| 跨行字符串 | `自定义字符串("{0} ` 换行 `", 玩家)` | 字符串内允许直接换行，接回一行 |
| 子程序里用 `事件玩家` | `子程序; Sub;` + `施加推力(事件玩家, …)` | **合法**：子程序继承调用方的事件上下文 |

**铁律**：多行合并必须**只合并、不改写**。第一版合并时我顺手把字符串抹成了空串，导致行号错位、插值检查全失效——真实样本立刻暴露。

**护栏**：合并超过 60 行仍未闭合就放弃并还原。否则一个引号判错会把后面整个文件吞进一条语句（实际发生过，报错指到 1451 行，其实是 500 行之后才闭合）。

**回归样本**：`tools/probes/real-idioms.ow` 固化了这五种写法。

## 三层检查（2026-10-22）：格式对了也可能导不进去

格式层全绿只说明"语法像工坊"，**名字过时、槽位类型错**一样导不进去，而且游戏给的报错完全指不到根因。
现在校验器多查两层，写模式时按这个顺序自查：

1. **格式层**：括号 / 分号 / 参数个数 / 事件参数个数 / 值函数当动作 …
2. **数据 ID 层**：地图 / 英雄 / 技能 / 按钮 / 设置键 / 事件名 必须存在于 `data/` 的当前版本表
3. **类型层**：玩家槽别塞数字、数值槽别塞玩家、子程序调用必须有声明、单条规则 ≤ 98KB、总元素 ≤ 32768

文案统一是 `X「Y」不在当前版本数据表里（可能已改名或移除）`——**看到这句就是版本差异，不是语法错**。

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 地图名过期 | 报「"地图("之后应有一个地图名称」 | `ws.py maps` 查当前 291 个有效名 |
| 英雄名过期 | 报「"英雄("之后应有一个英雄名」 | 对照 `data/heroes.tsv`（54） |
| 技能名过期 | 英雄设置键报「之后应有一个…」 | `data/abilities.tsv`（名字 + 所属英雄） |
| 设置键改名 | 报「"开启"之后应有一个游戏模式设置」 | `ws.py settings --mode <模式>` 生成合法键 |
| 事件名过期 | 报「之后应有一个队伍」 | `data/events.tsv`（14） |
| 玩家槽塞数字 | 报「之后应有一个玩家」 | `设置移动速度(本地玩家, 120)` |
| 数值槽塞玩家 | 导入失败或行为诡异 | 数值槽要 `数量(玩家)` / `生命值(玩家)` 这类取值函数 |
| 子程序没声明 | 报「未知的子程序」 | `调用子程序(X)` 前先在 `子程序` 块登记 |
| 单条规则超 98KB | 诊断面板「每条规则长度不得超过98KB」 | 一条规则塞太多动作就拆开，别指望游戏帮你数 |
| 元素数超 32768 | 诊断面板「总计元素数量」 | `ws.py count` 估算，大文件乘 2.12 |

**技能名在 .ow 里只出现在英雄设置键中**，两种形态（括号内 / 空格后）：

```
终极技能充能速度（鸡飞狗跳）: 100%
战斗时终极技能充能速度 鸡飞狗跳: 34%
```

英雄设置键**不要**自己拼技能中文名——技能改名是版本更新里最常见的一类破坏。

**行号保真**：跨行语句报错会指到内容真正所在的那一行，不是语句起始行。
看到报错行号时按"原文那一行"去数，别按你脑子里的合并后逻辑数。

## 校验器自己也会骗人（2026-10-22 复盘）

`strip_noise` 逐行处理，但被喂了**整篇文本**——它在第一个 `//` 处 `break`，于是所有基于
masked 文本的检查其实只看得到文件开头几行。真实模式长期"0 报错"，一半是这个 bug 遮出来的。

修法：`mask_text` 做**等长遮罩**（字符串 / 注释换成空格，长度和换行都不变），
既能全文扫描，又能用列偏移查 `SegMap` 换算行号。

**教训**：校验器"全绿"时必须拿真实文件反证一次；换实现（这里是 strip_noise → mask_text）
之后，误报会一次性涌出来——那才是真实覆盖面。修掉 6 类误报后才算真的全绿。

## 生成类工具必须独立复校（2026-10-22）

**规则**：任何「生成/改写文件」的工具（混淆器、批量生成器、模板填充），产物都要由**另一套代码**重新校验一遍，不能信生成器自己的自检。

两个真实案例，都是产物无法导入、而工具自己以为成功：

| 工具 | bug | 为什么自己的自检没发现 |
|---|---|---|
| `obfuscate_values` | 按旧字符串下标做替换，文本变长后位置错位，`全局.LifeguardX方向分量` 被切成 `全局.LifeX方向分量` | publish 自检只传了 `event_params` 一张表，比 `check` 弱，这一类名字错误根本不在它的检查范围内 |
| `obfuscate_indexes` | `("%f" % 0).rstrip("0")` 把 `0.000000` 削成 `0.`，写出非法数字 | 同上 |

修法有两条，缺一不可：

1. **统一校验入口**：`core.full_lint()` 同时被 `ws.py check` 和 `publish` 调用，杜绝「两套检查强度不一致」
2. **独立冒烟测试**：`tools/selfcheck_publish.py` 造样本 → 生成 → **再独立跑一遍 full_lint**，不复用生成器的结论

**同类教训**：`strip_noise` 在第一个 `//` 处 break，导致所有基于遮罩文本的检查只看得到文件开头——校验器自己坏了，所有「通过」都是假的。

判断一个检查器是否可信，只看一件事：**它读完了整个文件吗？它跑的是完整规则集吗？**

## 结束比赛的动作跟模式不匹配（2026-10-22 实测）

现象：查看器里明明显示了「宣布比赛为平局」执行了，**但比赛还在继续**。

原因：三个结束动作的适用范围是写死的，用错模式不会报错，只是没效果。

| 动作 | 生效范围 |
|---|---|
| `宣告玩家胜利(玩家)` | **只在自由混战（死斗）生效** |
| `宣告队伍胜利(队伍)` | 自由混战**无效** |
| `宣布比赛为平局()` | 自由混战**无效** |

所以给死斗做「时间到 → 平局」是做不到的，只能改成判某个玩家赢（比如击杀数最高者）。

校验器现在会直接拦：`「宣布比赛为平局」在死斗里无效（官方：此动作在自由混战模式中无效）`。

**另一个坑**：房间默认「比赛人满后」开始。单人测试时比赛根本没开始，倒计时跑完也不会触发结束动作。测试文件应在 `综合` 块里写 `游戏模式开始: 即时`。

## 队伍参数不能写「双方」（2026-10-22 实测）

```ow
范围内玩家(眼睛位置(事件玩家), 8, 双方, 关闭)     ❌
范围内玩家(眼睛位置(事件玩家), 8, 所有队伍, 关闭)   ✅
```

游戏报的是 **「第 44 行的"8,"之后应有一个值」**——指向的是半径那个数字，原因是它没能把「双方」认成合法队伍值，于是认为参数还没给完。

「双方」只用于**事件筛选**（`玩家造成最后一击; 双方; 全部;`）。队伍类参数用 `所有队伍` / `队伍1` / `队伍2`。

校验器现在会直接拦：`范围内玩家 的队伍参数不能写「双方」（那是事件筛选词）`。

## 字符串作参数必须包成 自定义字符串（2026-10-22 实测）

```ow
记入查看器("开始测试");                    ❌ 报「"记入查看器("之后应有一个值」
记入查看器(自定义字符串("开始测试"));        ✅
```

`.ow` 里没有"裸字符串"这种值——所有文本都要写成 `自定义字符串("…")`（或 `字符串("…")`）。

例外：**单独一行的 `"注释"` 是合法的**（那是字符串注释），不受影响。

校验器现在会拦：`记入查看器 的参数里不能直接写字符串，要包成 自定义字符串("…")`。

## 地图不是通用的（2026-10-22 实测）

`地图工坊室内`（GUID `972777519512064577`）只在**死斗**里能用。

给它配占领要点，游戏报 **「无效的地图设置」**——不说是哪张图不兼容，只说"无效"。

所以：

| 场景 | 做法 |
|---|---|
| 死斗测试 | 可以写 `启用地图 { 地图工坊室内 972777519512064577 }` |
| 其它模式 | **不写地图**，让游戏用该模式的默认图；或自己填一张该模式支持的图 |

`ws.py scaffold --mode 占领要点` 现在默认不写地图；要指定就加 `--map "艾兴瓦尔德 00000000068D.09F"` 这种。

校验器**查不出**这条：`data/maps.tsv` 里只有地图名和 GUID，没有"哪张图支持哪个模式"的数据。
