## 必查避坑清单

| # | 要点 |
|---|---|
| 1 | `添加至数组` 后读队首用 `[1]`，**不可用 `[0]` 或 `首个()`** |
| 2 | `字符串分割` 结果是 **1-indexed**，`假(0)`→第1项，`真(1)`→第2项 |
| 3 | `数组分割(arr, start, length)` 第3参数是**长度**非结束位置 |
| 4 | `截取字符串(s, start, length)` 第3参数同上是**长度** |
| 5 | `当前数组索引` 在映射/过滤中是 **0-based**，而 `添加至数组` 结果是 **1-indexed** |
| 6 | For 循环内创建持久效果时，**所有**用循环变量做索引的参数必须包裹 `单次赋值()` |
| 7 | While 循环内多个效果：**所有** `ID[i] = 最后创建的实体` 必须在 `i += n` **之前** |
| 8 | `追踪玩家变量频率` 目标值含动态表达式时必须用 `逐帧更新()` 包裹 |
| 9 | `等待(N, 当为“假”时中止)`：等待期间任一条件变假→整个动作列表立即中止 |
| 10 | `等待(N, 当为“真”时重新开始)`：条件持续为真→不断重置计时；条件变假→放行 |
| 11 | `中断` 只能跳出 `While`，**不能跳出 `For`**；For 提前退出用 `根据条件跳过(真, 大数)` |
| 12 | `开始限制阈值(0.010)` 锁定玩家但仍可读取阈值方向；`0` 则阈值返回零向量 |
| 13 | 退出 UI / 专用模式时，`可用按钮` 数量必须与进入时 `禁用按钮` **完全对称** |
| 14 | 进入 UI 模式后必须 `停止追踪玩家变量(事件玩家, face)`，否则锚定角漂移 |
| 15 | `|Y分量| > 0.9` 的极端仰角需夹紧为 0，防止水平角度计算失效（Gimbal Lock） |
| 16 | 生命池更新：先 `移除玩家的生命池(旧ID)` → 重新添加 → 保存 `最后创建的生命池` |
| 17 | 属性变量修改后必须调用对应同步函数（`设置造成伤害` / `设置最大生命值` 等） |
| 18 | `创建地图文本` 两种签名参数顺序不同（三段 9 参数 vs 单文本 8 参数），**不可混用** |
| 19 | `设置状态(玩家, 助攻者, 状态, 时长)` 第 2 参数是助攻者（填 `空`），第 3 才是状态名 |
| 20 | 三元时长技巧：`设置状态(玩家, 空, 状态, 条件 ? 9999 : 0)` 代替 If-Else + 清除状态；三元虽整体受支持，但不要直接用于某些动作的枚举参数位（如 `播放效果` 的声音类型），例如 `播放效果(玩家, 条件 ? 正面状态施加声音 : 负面状态施加声音, ...)` 可能导入失败，此类情况改用 `If / Else` |
| 21 | HUD 可见参数优先用 `本地玩家` 或三元 `条件 ? 本地玩家 : 空`，避免 `所有玩家()` |
| 22 | `从数组中移除(A, B)` = 集合差 A-B，可嵌套实现多重排除 |
| 23 | `开始规则` 的子程序行为：`重新开始规则` = 规则已运行则重新开始；`无动作` = 规则已运行则跳过，适合异步后台任务 |
| 24 | 多段 HUD 可见性切换：所有阶段 HUD 一次性创建，靠状态变量控制，**不要反复销毁重建** |
| 25 | 槽位错开延迟：`等待(0.016 + 栏位 * 步进, 当为“假”时中止)` |
| 26 | For 循环内找到目标后提前退出：`根据条件跳过(真, 足够大行数)` 模拟 break |
| 27 | `继续` 只在 `While` 中有效，跳回循环顶部；与 `中断`（跳出）完全不同 |
| 28 | `0.000 == 假` 使规则永不触发（用于模板占位），比 `禁用 规则(...)` 仍占元素配额 |
| 29 | 变量边缘检测：副本变量必须与被检测变量**初始值相同**，否则游戏开始时误触发 |
| 30 | 玩家显示名无直接函数，只能用 `字符串包含(自定义字符串("{0}", 玩家), 关键词)` 检测 |
| 31 | `数组值的索引` 返回 -1 表示不存在；`-1 % n` 在工坊中可能返回负数，需注意 |
| 32 | `最后(已排序的数组(玩家列表, 统计值))` = 取最大值玩家；`首个()` = 最小值玩家 |
| 33 | `正在集结英雄` 为真 = 英雄选择阶段；等待结束用 `等待直到(正在集结英雄 == 假, 99999)` |
| 34 | 需要 `扩展 { 光束效果 }` 才能用 `创建光束效果`；其他扩展项同理 |
| 35 | `单次赋值()` 缓存在**整个规则执行周期**内，`如条件为“真”则循环` 循环回来不会重新采样。用它做 `等待直到` 变化检测时，循环第二次起旧值永远等于当前值 → 立即放行 → 无限循环 |
| 36 | 审查 `Else If(A != X && 真)` 时，冗余的只是 `&& 真`，**不等价于 `Else`**。`Else If(A != X)` 与 `Else` 覆盖范围不同：前者不覆盖 `A == X` 的情况，后者全覆盖 |
| 37 | `持续 - 全局/每名玩家` 规则若动作块内**无 `While` 也无 `等待`**，只要条件持续为真就会每帧重新执行。修复方式：加 `等待(0.016, 无视条件)` 或加“已执行过”守卫（如 `数量(全局.X) == 0`） |
| 38 | `修改变量(V, 添加至数组, X)` 会使变量 V 变为 **1-indexed**（[0] 为空哨兵）。但 `已过滤的数组`、`映射的数组` 等值函数返回的是 **0-indexed** 新数组。初始化数据表推荐改用 `在索引处设置全局变量(V, N, 值)` 逐项写入 |
| 39 | `中止` / `根据条件中止` 在子程序（`调用子程序` 调用的规则）内执行时，会**穿透子程序边界**中止整个调用方规则的动作列表，而非仅停止子程序本身。子程序内需要提前退出时应改用 `If/Else/End` 守卫 |
| 40 | `与此方向的垂直角度(面朝方向(玩家))` **向上看返回负值**。用视角垂直角映射列表光标时公式为 `(0.5 + 角度 / 范围) * 数量`，误用减号会导致上下选择颠倒 |
| 41 | 同一 `创建HUD文本` 的标题 / 子标题 / 文本三槽字号不同；需要多色且同字号时，**不要把不同内容硬塞进同一 HUD 的三个槽**，具体排版说明看 `ui-notes.md` |
| 42 | 以下函数名中的引号**必须使用中文弯引号**（U+201C `“` / U+201D `”`），用英文直引号（U+0022 `"`）会导致语法错误无法识别：`当为“假”时中止`、`当为“真”时重新开始`、`对任意为“真”`、`对全部为“真”`、`如条件为“真”则循环`、`如条件为“假”则循环`、`如条件为“真”则中止`、`如条件为“假”则中止` |
| 43 | `持续 - 每名玩家` / `持续 - 全局` 规则里创建 `HUD / 地图文本 / 效果` 时，**资格判断要尽量前置到条件块**；不要只在可见参数里写 `条件 ? 所有玩家(...) : 空数组/空`，否则不满足资格的对象也可能仍然执行创建路径，导致多人房初始化负载放大 |
| 44 | 审查 `创建效果(..., 重新赋值)` 时，若刷新模式包含 `位置` / `半径` / `颜色` / `可见`，应按**常驻动态对象**处理，而不是一次性静态效果；多人房下总负载 = 单玩家对象数 × 玩家数 |
| 45 | 纯装饰类常驻特效（称号光环、管理员环绕、小光球等）必须同时检查 4 件事：**谁会创建、12 人房最多创建多少个、是否持续重评估、何时销毁**；任一项不清楚都应判为高风险 |
| 46 | 常驻视觉对象若**没有保存实体/文本 ID**，且没有对应的 `消除效果` / `消除HUD文本` / `消除地图文本` 路径，默认视为**缺少回收通道**；遇到身份变化、重进、切模式、重新初始化时容易残留或累积 |
| 47 | `全房可见` 的玩家装饰对象要按**按玩家数线性放大**审查：例如“每名玩家 2 个特效”在 12 人房就是最多 24 个常驻对象；若只是装饰，不应默认给 `所有玩家(所有队伍)` |
| 48 | 对装饰对象，优先级应低于玩法提示对象；元素预算紧张时，**先降级装饰特效**（减少环绕数量、改静态、改本地可见、改近距离可见），不要先动核心玩法提示 |
| 49 | 多名玩家可能在同一时刻进入初始化规则时，常驻 HUD / 地图文本 / 特效应优先考虑**按栏位错峰创建**，用 `等待(0.016 + 栏位(事件玩家) * 步进, 当为“假”时中止)` 分散首帧创建尖峰 |
| 50 | `已过滤的数组(...)`、`映射的数组(...)` 等复杂返回值在部分上下文里直接写 `[0]` 可能触发导入解析错误；遇到这类组合表达式时，优先改写为 `数组中的值(..., 0)` 再参与外层计算 |
| 51 | 审查密码 / 权限输入逻辑时，若原系统已采用 `syntax.md` 里的数值混淆，**不要**为了“更直观”把它改成明文字符比较或明码按钮序列；这会破坏原本的防泄露设计 |
| 52 | `自定义字符串(...)` 仅支持 `{0}`、`{1}`、`{2}` 三个占位符；`{3}` 及以上会触发导入解析错误。需要拼 4 段及以上内容时，应改用嵌套 `自定义字符串(...)`，不要继续扩展占位编号 |
| 53 | 旧名字还在数据里，但可能已经没有行为：官方对工坊维护不勤，被移除或重做的技能，其效果名、声音名、状态名常常仍留在数据里——导入不报错，游戏里却什么也不发生。判断“名字存不存在”看数据，判断“有没有效果”只能实机跑（最小隔离测试见 `diagnostics.md`） |
| 54 | 按槽位写，不按技能写：`主要攻击模式` / `辅助攻击模式` / `技能1` / `技能2` 这些按钮槽位永远有效，槽位里装什么技能跟着版本换（例：路霸的辅助攻击模式空过、装过回血、现在是废品压缩器）。别假设槽位当前是什么技能；要确认就按一次看效果，或 `记入查看器` 打印出来 |
| 55 | 变量名和子程序名**只能用英文**（字母、数字、下划线，≤ 32 字符）。`0: 计数器` 这种中文名导入必失败；规则名、模式名称、描述这些是引号里的字符串，可以写中文。生成代码时中文只出现在字符串、枚举和函数名里 |
| 56 | 设置块、变量块、事件块都不要手写：从 `golden.ow` 复制结构再改值。`综合` 块的位置、键的顺序、枚举写法都是格式的一部分，手拼会在 `综合 {` 处报「之后应有一个游戏模式设置」这类错误 |
| 57 | `子程序` 块和 `变量` 块一样是 `索引: 名字`，不是可执行语句，不加分号；名字只能英文 |
| 58 | 设置块里的键值只能从 `golden.ow` / `golden2.ow` 抄，**枚举值不要自造**。`允许切换英雄` 合法值是 `允许/禁用`，写 `启用` 会报「`综合 {` 之后应有一个游戏模式设置」——报错指块头，真错在块里第一个值。改设置只改数字百分比（如 `伤害量: 100%`），不动枚举 |
| 59 | `综合` 块只认 `复生时间` / `急救包刷新` / `游戏模式开始` / `英雄限制` 四个键；换成 `允许切换英雄`、`随机英雄复生` 会报「`综合 {` 之后应有一个游戏模式设置」。设置块的键和值一律照 `golden3.ow` 抄，只改数字 |

## 工坊执行机制（实测 2026-10-20）

- **`持续` 规则不会自己重入**。写成 `持续 - 全局` + `修改全局变量(n, 加, 1);`，10 秒后变量仍是 1——规则只执行了一次。
- **要持续做事必须显式循环**：`While(真); …动作…; 等待(0.1, 无视条件); End;`。同一条规则实测 3 秒 27 次、10 秒 90 次。
- 只加 `等待` 不算循环（`加1; 等待(0.1);` 实测仍是 1），必须 `While` 撑住。
- 推论：任何"每帧/定时"逻辑（HUD 刷新、计时器、状态检查、距离检测）都要按 `While(真)` 模板写；事件驱动的逻辑（伤害、击杀、按键）直接绑事件，不要靠轮询。

## HUD 的正确写法（实测 2026-10-20）

- **HUD 文本里的变量引用自动刷新**：`创建HUD文本(…, 自定义字符串("{0}", 全局.totalKills), …)` 建一次即可，数字会跟着变量变，**不要重复创建**
- 重复创建会堆叠：每条都会新增一行（实测 4 次击杀 → 4 行 HUD，虽然每行显示的都是最新值）
- 刷新槽的具体取值对"是否堆叠"没有影响
- `持续` 规则只执行一次，所以变量自增要靠**事件**（击杀、按键、受伤）或 `While(真)` + `等待`，不能指望规则自己跑第二遍
- 结论模板：HUD 建一次 + 变量由事件维护 = 活数字；不要用循环刷 HUD
