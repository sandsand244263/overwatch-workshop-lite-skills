## HUD / UI 说明补充

这些内容更偏显示层经验，不属于“必查避坑清单”，但在做 HUD / 地图文本排版时很有用。

### 多色文本

- 多色文本的稳定做法，是把每个需要独立着色的元素拆成单独 HUD。
- 如果希望字体一致，优先让这些 HUD 都使用同一槽位，例如统一使用标题槽。
- 不要把不同内容分别塞进同一 HUD 的标题 / 子标题 / 文本三槽里，这三槽字号不同。

### HUD 三槽大小

- `创建HUD文本` 三槽字体大小顺序：**标题 > 文本 > 子标题**。
- 同一 HUD 内空槽不占纵向空间，不会额外留白。

### HUD 坐标与排序

- `左边` / `右边` 在文本很短时可以形成左右分列；文本一长，往往会趋向居中，设计时不要过度依赖短文本分列。
- `排序` 数值越小越靠上，负数合法。
- 同一坐标下，`左边` 与 `右边` 共用同一套纵向排序空间。
- 同排序值的多条 HUD，通常是先创建的排在上面。

### 进度条 HUD

- `创建进度条HUD文本` 整体趋向居中显示，不要按普通 HUD 的左右列思路布局。
- 进度条从左到右填充，文字标签显示在进度条下方。

### 视觉层建议

- 玩法提示对象优先级高于装饰对象。
- 做多人模式时，HUD、地图文本、常驻特效最好分别做预算，不要把所有显示层对象都塞进一个“反正能显示”的思路里。
