# 工坊元素成本参考

这份表用于“省元素审查”。

记录方式统一为：

- `基准 -> 测试, 差值`
- 差值是相对该组基准的变化
- 不同组之间不能直接横向比较，必须先看它属于哪一组

## 基准说明

- `全局基准 = 3`
  - 模板：`持续 - 全局` + `设置全局变量(A, 0);`
- `玩家基准 = 3`
  - 模板：`持续 - 每名玩家` + `设置玩家变量(事件玩家, A, 0);`
- `映射基准 = 8`
  - 模板：`映射的数组(数组(0), 0)`
- `过滤基准 = 7`
  - 模板：`已过滤的数组(数组(0), 真)`
- `排序基准 = 10`
  - 模板：`已排序的数组(数组(2, 1), 0)`
- `普通条件基准 = 6`
  - 模板：条件 `0 == 0`
- `规则结构基准 = 3`
  - 模板：1 条最小全局规则
- `子程序基准 = 3`
  - 模板：1 条最小主规则

## 当前可直接使用的规律

1. `真 / 假 / 空 / 事件玩家 / 当前数组元素 / 当前数组索引` 这类值很轻，很多时候比 `0` 更省。
2. 玩家常见轻量值大多是 `+0`，例如 `所选位置`、`眼睛位置`、`面朝方向`、`速度`、`英雄(...)`、`按键(...)`。
3. `数组(...)` 和 `自定义字符串(...)` 都是稳定递增型，适合直接按参数数量估成本。
4. `过滤 / 排序 / HUD / 效果 / 规则结构` 往往才是真正容易把元素打满的部分。
5. 如果想先省元素，优先考虑少建 HUD、少建效果、少用复杂排序、少堆分支和循环。
