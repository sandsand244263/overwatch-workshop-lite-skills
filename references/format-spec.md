# 格式规范（照这个写才导得进去）

这份文件只管**格式**，不管玩法设计。写代码前先确认这里的结构，生成后跑一遍 `scripts/lint_ow.py`。

## 一、文件骨架（顺序固定）

```ow
设置
{
	主程序
	{
		模式名称: "模式名"
		描述: "说明"
	}

	模式
	{
		死斗
	}

	扩展
	{
		减益状态效果
	}
}

变量
{
	0: counter
}

规则("规则名")
{
	事件
	{
		持续 - 全局;
	}

	条件
	{
		比较式 == 真;
	}

	动作
	{
		函数(...);
	}
}
```

顺序：`设置` → `变量` → `子程序` → 一条或多条 `规则`。缩进用 Tab 或空格都行，但同一文件里保持一致。

## 二、硬规则（违反就导入失败）

| # | 规则 | 细节 |
|---|---|---|
| 1 | 每条语句以 `;` 结尾 | 块收尾的 `}` 后面**不加**分号 |
| 2 | 设置块是 `键: 值` | 不是语句，不加分号；冒号用半角 |
| 3 | 变量声明 `索引: 变量名` | 索引 0–127，可跳号；变量名只能是英文字母/数字/下划线，≤ 32 字符 |
| 4 | 字符串用英文双引号 | `"文本"`，内部引号写 `\"`；**中文弯引号只用在函数名里**（如 `如条件为“真”则循环`） |
| 5 | 参数用半角逗号分隔 | **不许尾逗号**：`)` 前不能有逗号 |
| 6 | 条件块每行必须有比较运算 | `== != > < >= <=`；只写一个值会报「应有一个关系运算子」 |
| 7 | 注释只有两种 | `// 单行`、`/* 多行 */`；`#` 不是工坊注释 |
| 8 | 没有 `===` | 赋值 `=`，比较 `==` |
| 9 | 参数个数不超过签名 | 见 `signatures.md`；尾部参数可以省略 |
| 10 | 「可见」参数填玩家或玩家列表 | 不是真假值；默认 `所有玩家(所有队伍)` |
| 11 | `持续 - 全局` 规则里不能用 `事件玩家` | 会失效，改用 `本地玩家` |
| 12 | 变量名不能只有大小写差别 | 工坊把它当同一个变量，会冲突 |
| 13 | 英雄子设置用 `开启/关闭` | 游戏自己导出的 `启用/禁用` 在这里是错的 |
| 14 | 地图 id 不能是 0 | 会直接导致导入报错 |

## 三、生成时的查表顺序

1. **名字存不存在** → `actions.md`（动作）、`values.md`（值/条件）、`strings.md`（内置字符串）、`enums.md`（枚举、地图、英雄）
2. **参数几个、什么顺序** → `signatures.md`（225 个动作 + 266 个值函数）
3. **格式对不对** → 本文件；写完跑 `scripts/lint_ow.py`
4. **名字还在不在、有没有行为** → `diagnostics.md` 的最小探针（数据里有名字 ≠ 游戏里有效果）

## 四、常见导入报错对照

| 游戏报什么 | 多半是 |
|---|---|
| 应有一个关系运算子 | 条件没写比较运算 |
| 语法错误 / 意外的符号 | 尾逗号、缺分号、`===`、混进了全角标点 |
| 变量名无效 | 变量名写了中文 |
| 参数数量不对 / 参数无效 | 参数个数超过签名，或顺序错了 |
| 类型不匹配 | 可见位置填了 `真/假`，数值位置填了字符串 |
| 缺少右括号 / 花括号 | 括号没配对（多层嵌套时最容易漏） |

## 五、一条硬性交付标准

生成或修改完 `.ow` 后，**先自己跑校验，再交给用户**：

```bash
python scripts/lint_ow.py 你的文件.ow
```

必须 0 错误。有错就先改代码，不要让人肉导入去发现问题——那是最后一道关，不是第一道关。
