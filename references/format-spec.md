# 格式规范（照这个写才导得进去）

基准文件：`golden.ow`（从游戏里“复制脚本”导出的真实文件）。本文件所有结构都以它为准，不要凭印象补。

## 一、文件骨架

```ow
设置
{
	主程序
	{
		模式名称: "模式名"
		描述: "说明"
	}

	大厅
	{
		比赛语音聊天: 启用
		观战者人数上限: 6
		返回大厅: 从不
	}

	模式
	{
		死斗
		{
			启用地图
			{
				黑森林 972777519512063901
			}
		}

		综合
		{
			游戏模式开始: 即时
			急救包刷新: 开启
			英雄限制: 关闭
		}
	}

	英雄
	{
		综合
		{
			被动生命值恢复: 禁用

			路霸
			{
				伤害量: 10%
			}

			启用英雄
			{
				路霸
			}
		}
	}
}

变量
{
	全局:
		0: totalKills

	玩家:
		0: streak
		1: boostReady
}

规则("规则名")
{
	事件
	{
		持续 - 每名玩家;
		双方;
		全部;
	}

	条件
	{
		按钮被按下(事件玩家, 按钮(互动)) == 真;
	}

	动作
	{
		大字体信息(事件玩家, 自定义字符串("你好"));
	}
}
```

顺序固定：`设置` → `变量` → `子程序`（可选）→ 一条或多条 `规则`。

## 二、变量块必须分两段

```ow
变量
{
	全局:
		0: totalKills

	玩家:
		0: streak
		1: boostReady
}
```

- 段标签带冒号：`全局:` / `玩家:`，变量声明缩进一层
- **两个段的索引各自从 0 开始**，互不影响
- 只写 `0: xxx` 不写段标签，会报「`变量 {` 之后应有 `全局`」
- 引用：全局写 `全局.名字`，玩家写 `事件玩家.名字` / `本地玩家.名字`

## 三、事件块：1 行或 3 行

```ow
事件
{
	持续 - 全局;
}
```

```ow
事件
{
	持续 - 每名玩家;
	双方;
	全部;
}
```

- 只有全局事件是 1 行；**其它所有事件必须 3 行**：事件类型 → 队伍过滤 → 英雄过滤
- 写 2 行会报错（overpy 解析器原话："either 1 (global) or 3 (every other event)"）
- 队伍过滤：`双方` / `队伍1` / `队伍2`；英雄过滤：`全部` 或具体英雄

## 四、控制流用英文关键字 + 分号

```ow
While(正在空中(事件玩家) == 真);
	施加推力(事件玩家, 上, 6, 至地图, 取消相反运动);
	If(按钮被按下(事件玩家, 按钮(蹲下)) == 真);
		施加推力(事件玩家, 下, 12, 至地图, 取消相反运动);
	Else If(按钮被按下(事件玩家, 按钮(跳跃)) == 真);
		施加推力(事件玩家, 上, 6, 至地图, 取消相反运动);
	End;
	等待(0.016, 无视条件);
End;
```

单行写法 `如条件为“真”则循环;` 也存在（`golden.ow` 里就在用），多分支一律 `If / Else If / End`。

## 五、硬规则

| # | 规则 | 细节 |
|---|---|---|
| 1 | 每条语句以 `;` 结尾 | 块收尾的 `}` 后面**不加**分号 |
| 2 | 设置块是 `键: 值` | 不是语句，不加分号；冒号半角 |
| 3 | 变量名只能是英文 | 字母/数字/下划线，≤ 32 字符；中文名必失败 |
| 4 | 字符串用英文双引号 | `"文本"`，内部引号写 `\"`；`\n` 可换行 |
| 5 | 参数用半角逗号分隔 | **不许尾逗号** |
| 6 | 条件块每行必须有比较运算 | `== != > < >= <=` |
| 7 | 注释只有 `//` 和 `/* */` | `#` 不是注释 |
| 8 | 没有 `===` | 赋值 `=`，比较 `==` |
| 9 | 参数个数不超过签名 | 见 `signatures.md`，尾部参数可省 |
| 10 | 「可见」参数填玩家 | 不是真假；常用 `事件玩家` / `本地玩家` / `所有玩家(所有队伍)` |
| 11 | 颜色写成 `颜色(x)` | 例如 `颜色(白色)`，不能裸写 `白色` |
| 12 | 空值写 `空` | HUD 的子标题/文本可以填 `空` |
| 13 | `持续 - 全局` 里不能用 `事件玩家` | 用 `本地玩家` |
| 14 | 长参数可以跨行续写 | 括号没闭合就继续，续行不要求分号 |
| 15 | 地图写 `名字 GUID` | 例如 `黑森林 972777519512063901` |
| 16 | 英雄设置用 `开启/关闭` | 游戏自己导出的 `启用/禁用` 在这里是错的 |

## 六、生成时的查表顺序

1. 结构 → 本文件 + `golden.ow`
2. 参数个数与顺序 → `signatures.md`
3. 名字存不存在 → `actions.md` / `values.md` / `strings.md` / `enums.md`
4. 行为有没有 → `diagnostics.md` 的最小探针

## 七、常见导入报错对照

| 游戏报什么 | 多半是 |
|---|---|
| `变量 {` 之后应有 `全局` | 变量块缺 `全局:` / `玩家:` 段标签 |
| 应有一个关系运算子 | 条件没写比较运算 |
| 语法错误 / 意外的符号 | 尾逗号、缺分号、`===`、全角标点 |
| 参数数量不对 / 参数无效 | 参数个数超过签名 |
| 类型不匹配 | 可见位置填了 `真/假`，数值位置填了字符串 |
| 事件参数缺失 | 事件块写成 1 行，但这不是全局事件 |

## 八、交付前必跑

```bash
python scripts/lint_ow.py 你的文件.ow
```

必须 0 问题。`golden.ow` 是回归基准，它自己必须始终 0 问题——跑出问题说明校验器改坏了。
