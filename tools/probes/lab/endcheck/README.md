# 探针：少一个 `End;`，游戏到底拦不拦（1 格）——已测完（E-61）

## 读数（2026-10-24，用户实机一次）

| 观察 | 结果 |
|---|---|
| 导入 | **通过，不报错** |
| 查看器 | `[00:00:08] [e1] A=1` —— **只有这一行** |
| 按写法应有的结果 | `A=1`、`A=2`、`A=3` 三行（循环体内无等待，同一秒打完） |

**两条结论**

1. **游戏不拦**「少写 `End;`」。动作块**末尾**的 `End;` 本来就可以合法省略（用结尾的 `}` 收尾），
   9 份真实语料里 5 份这么写（《暴打大锤3》《猪猪钩钩乐·原版》等能正常玩的模式）。
2. **但行为变了**：缺 `End;` 时循环体**只执行一次**。不报错、不提示，量出来的结果和写的意图不一样。

## 文件

`endcheck-noend.ow`：一条 `持续 - 全局` 规则，`While(全局.A < 3);` 起了头、**故意不写 `End;`**：

```
动作
{
	等待直到(正在设置 == 假, 60);
	While(全局.A < 3);
		全局.A = 全局.A + 1;
	记入查看器(自定义字符串("[e1] A={0}", 全局.A));
}
```

- 无死循环风险：`A` 从 0 加到 3，条件自然为假。
- 默认 `check` 判「可以导入」（只 1 条隐蔽提示）—— 就是要有意放它过去。

## 决定：把那条检查撤掉，不升必改

原本的计划是「游戏拦 → 升必改」。实际是游戏不拦，那就不该报「会挡导入」。

但也不能改成提示：要判「忘写 End」就得数 `If/While` 与 `End;`，而这件事**分不清故意省和忘了写**。
实测旧实现（按行内 `While(` / `If(` 出现次数对账）在 9 份真实语料上**误报 5 份，而且两个方向都错**
（既报「开头 1 个 / End 0 个」，也报「开头 2 个 / End 3 个」），超 D-006 门槛（>3 条即撤）。

→ 整条删除（`core.check_balance` 现在只查括号）。知识改由 `docs/pitfalls-runtime.md` 承载，
断言写进 `docs/rules.tsv`（`检查=不接`），等级 L3（有读数）。

本探针留作回归样本：以后动解析相关逻辑时重跑，读数应该还是「仅一行 A=1」；
哪天读到 3 行，说明游戏改成按块尾补齐 `End;` 了，这条断言要改等级。

## 怎么导、怎么读

1. 导入 `endcheck-noend.ow`
2. **记下导入时有没有报错弹窗**（有就抄原文，`ws.py locate "原文"` 能指到行）
3. 进比赛跑 10 秒，退到大厅再退游戏
4. `python tools/ws.py readlog --expect-file endcheck-noend.expect.tsv`
   期望表写的是 **1**（实测行为），不是代码意图的 3 —— 读到 1 是「符合已测结论」，
   读到 3 才是「游戏改了行为，断言要升级」。

只占用户 2~3 分钟，不用玩，读完就能退。
