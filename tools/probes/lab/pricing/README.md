# 探针：大数组是否线性计价（2 个文件，不是 2 格）

## 为什么是 2 个文件

`总计元素数量` 是**整个模式**的合计，读数是「一个模式的元素总数」。
把 3 项数组和 120 项数组塞进同一个文件，两个数会被加在一起，分不出来谁贵。
所以拆成两个文件：除数组长度外**逐字节相同**（`diff` 可验），差值就是数组长度差价的净值。

## 要验的假设

元素估算模型（`docs/limits.md` §四）：`数组(...)` = 2 + 各各项，每个数字 = 2。

| 文件 | 数组 | 模型估价 | 模型差价 |
|---|---|---|---|
| `pricing-array-3.ow` | `数组(1..3)` | 9 | — |
| `pricing-array-120.ow` | `数组(1..120)` | 243 | **234** |

- **线性**（模型对）：实测差价 ≈ 234（允许 ±6 的小规模偏差）
- **非线性**（数组按条收费/有别的累计规则）：实测差价明显偏离 234 —— 差值本身就是新系数，回填 `docs/limits.md`
- **固定价**（整个数组算常数）：实测差价 ≈ 0

这一格是「搜打撤 −17.8% 缺口」剩下的**唯一未验假设**（`tools-maintainer/v5-c1/C1-REPORT.md` 把逆向那条路封了）。

## 怎么导、怎么读

两格都是**静态计数探针**，不需要进比赛、不需要玩，读完数就能退：

1. 导入 `pricing-array-3.ow`
2. 地图工坊 → **显示诊断结果** → 读 `总计元素数量` → 记下数字
3. 退回大厅，导入 `pricing-array-120.ow`，同样读一次
4. 退到大厅再退游戏（直接结束进程日志可能不落盘）

两个读数发回来即可，`acceptance-lab/runtime/README.md` 里回填一行。

## 预期内的 2 条提示（不影响导入）

`check` 会提示「没有 记入查看器」「没做工位隐蔽」——这两条是给**运行时探针**的规范。
本探针只读诊断面板的静态计数，不加计数器、不加隐蔽动作，因为它们本身也占元素、会污染读数。
