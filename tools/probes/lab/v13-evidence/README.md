# v13 证据探针：6 个「用户会踩但没实机读数」的检查

这一组的用途不是读数字，是**换报错原文**：这 6 条检查现在只有数据表或官方说明撑着（证据 L1~L2），
没有一条带「游戏真的拒了 / 真的没拒」的读数。按 `docs/rules.tsv` 的档位纪律，L1 不能当结论，
所以它们至今不能立事实行。

**一格一文件**是硬要求：导入被拒是整份文件拦下，塞在一个文件里就只剩第一条的报错。

## 怎么跑（三句话）

1. **文件**：本目录 7 个 `.ow`——`base.ow` 是对照组，`c1`~`c6` 各测一个写法。
2. **怎么跑**：游戏 → 工坊 → 逐个导入 → 「开始」；`base` 必须能进游戏，其余 6 个大概率在导入时就弹错。
3. **看哪里**：导入被拒的，**把弹窗那条报错原文照抄给我**（照抄，不要改字）；
   导入成功的，进游戏开查看器 → 「将当前记录复制到剪贴板」→ 贴回来（找 `[cN]` 开头的行）。

一次跑完大约 5 分钟；`c3` 是唯一需要进游戏看行为的（进去后站着等 3 秒，看是否直接进结算页）。

## 每格在问什么

| 格 | 写法 | 现在卡在哪 |
|---|---|---|
| `base` | 只有一行 记入查看器 | 对照组：它导入成功，才能说明后面「被拒」是那一行造成的 |
| `c1` | `记入查看器("[c1] 裸字符串这一行")` | 检查判必改（报错表有对应文案），**没有实机读数** |
| `c2` | `i = 1;`（i 已声明） | 同上，只有错误码 67738 |
| `c3` | 死斗里 `宣告队伍胜利(队伍1)` | 官方说自由混战无效，但**没验过是拒导入、还是能导入不生效** |
| `c4` | 地图编号 `972777519512069999` | 检查只给提示（怕误伤），想知道游戏到底拦不拦 |
| `c5` | `获胜得分: 9999` | E-16 说「外部写进 .ow 再导入会报错」，但没验过模式页的数值键 |
| `c6` | `创建HUD文本(…, 中间, …)` | 下拉值检查默认关着（怕误报），先看游戏拦不拦 |

## 读回来之后怎么判（写死在 `expect.tsv` 里）

| 结果 | 结论 |
|---|---|
| 6 个全被拒 | 6 条检查都能升「必改」并立事实行（依据 = 本轮实机） |
| 有的导入成功 | 那几条只能留提示级，事实行的「证据」列写 L2，不许写 L3 |
| `base` 也被拒 | 说明文件本身有问题（可能是地图/大厅段），先修基座，其余结论作废 |

## 本轮顺带发现的检查缺陷（记下来，下轮修）

`check_game_end_actions` 按文本找动作名，**写在 `描述:` 字符串或规则名里也会被报**：
第一版 c3 的 `描述: "…死斗里宣告队伍胜利"` 触发了同一条必改，一份文件报出 4 处（实际只有 1 处是真的）。
修法方向：只在「动作块」的语句行里找，或先 `strip_noise` 再匹配。
