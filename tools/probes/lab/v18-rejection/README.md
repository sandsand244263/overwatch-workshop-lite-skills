# v18 被拒探针（故意写坏的文件）

这一包和 `lab/v17-evidence/` 相反：**这些文件本来就不该通过 `ws.py check`**。
目的是证明「我们说是错的东西，游戏真的会拒」——也就是给 `check_balance` / `check_duplicate_blocks` /
`check_percent_operator` 的 `50%` 分支补读数。

判读口径：**导入被拒就是通过**。把游戏弹出的报错原话抄下来（截图或打字都行），
记进私有仓 `import-log.tsv`（`故意被拒 = 是`）和 `v17-re/probe-readings.tsv`。

| 文件 | 故意写坏了什么 | 要证的说法 |
|---|---|---|
| `P16-missing-paren.ow` | 动作里少一个右括号（左 4 右 3） | 括号不配对 → 游戏直接报错 |
| `P17-duplicate-var-block.ow` | 顶层「变量」块写了两份 | 重复块 → 游戏拒绝（大概报「未知的变量」一类） |
| `P18-percent-sign.ow` | `设置受到伤害(事件玩家, 50%)`，且事件改成 `持续 - 每名玩家` 以隔离这一个错 | `%` 是取余运算符，写 `50%` 会被拒（「之后应有一个值」） |
| `P19-mode-ui-6v6.ow` | 模式块写界面名 `占领要点（6V6）` | 界面名不能写进 `.ow`（括号形式此前只有同类推断，没有读数） |
| `P20-mode-ow-6v6.ow` | 同一份设置，模式块写 `占领要点 6v6` | 对照组：ow_name 应该能导入（P19 被拒才有意义） |

**P19/P20 是一对**：先导 P19（预期被拒），再导 P20（预期成功）。两个都拒说明问题不在模式名上。

**别修好再导入**——修好就验不了了。这三个文件也不要拿去当模板抄。
